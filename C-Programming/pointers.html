👉 13. Pointers

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

13.1 Four Pointer Ideas to Keep Separate

int x = 25;
int *p = &x;
ExpressionMeaning
xvalue stored in object x
&xaddress of x
ppointer value stored in p; here it equals &x
*pobject/value reached by dereferencing p
&paddress of the pointer object p itself
example addresses
0x1000: x = 25
0x2000: p = 0x1000
             │
             └── points to x

13.2 Pointer Declaration Syntax

int *p;
int *a, *b;
int *onlyPointer, ordinaryInt;

The * is associated with each declarator. In the final declaration only onlyPointer is a pointer; ordinaryInt is an int. Many style guides declare one pointer per line to reduce visual confusion.

13.3 Initialization and Validity

int x = 10;
int *p = &x;
int *q = NULL;

A pointer should either point to a live object/function as permitted, be a valid one-past pointer for limited arithmetic/comparison use, or hold a null pointer value when representing “no object.” An uninitialized pointer has an indeterminate value and must not be dereferenced.

13.4 Dereferencing Requires a Valid Pointed-To Object

*p = 50;        /* modifies x when p == &x */
printf("%d", *p);

Dereferencing converts a pointer relationship into access to the pointed-to object. A null, dangling, invalid or inappropriate one-past pointer cannot be dereferenced safely.

13.5 Pointer Type Matters

Pointer arithmetic and dereference behavior depend on the pointed-to type. Incrementing an int * conceptually moves to the next int, not one raw byte.

int a[3] = {10,20,30};
int *p = a;
p++; /* now points to a[1] */
Address diagrams are conceptual

If sizeof(int) is 4 on a particular system, the numeric address may increase by 4, but portable C reasoning should say “advance by one int element.”

13.6 Arrays and Pointers Are Related but Not the Same

An array is an array object with fixed extent. In most expressions, an array expression is converted to a pointer to its first element. This conversion creates the close relationship, but the array itself is not a pointer variable.

int a[5];
int *p = a;

sizeof a; /* size of whole array */
sizeof p; /* size of pointer */

13.7 Array-to-Pointer Conversion Exceptions

The array-to-pointer conversion does not occur in every context. Important examples include when an array is the operand of sizeof and unary &. These cases help explain why sizeof array can still see the full array size where the array object is in scope.

13.8 Pointer Arithmetic — Legal Domain

int a[5];
int *p = &a[1];
int *q = p + 2;   /* &a[3] */
ptrdiff_t d = q - p; /* 2 */

Pointer arithmetic is defined relative to the same array object (with a permitted one-past position). Arbitrarily adding integers to unrelated addresses or subtracting pointers into unrelated objects is not portable C.

13.9 One-Past Pointer

int *begin = a;
int *end = a + n;
for (int *p = begin; p != end; ++p)
    printf("%d ", *p);

end may legally point one element past the array so it can act as a boundary marker. It must not be dereferenced.

13.10 void * — Generic Object Pointer

void *vp = &x;
int *ip = vp;
printf("%d", *ip);

void * can represent a pointer to an object without specifying its object type. Standard C permits conversions between object pointers and void *. You cannot directly dereference void * because the pointed-to type/size is unknown, and arithmetic on void * is not standard C.

13.11 Pointer to Pointer

int x = 10;
int *p = &x;
int **pp = &p;

printf("%d", **pp);
pp → p → x
     address  value
pp stores address of pointer p; p stores address of int x

A pointer-to-pointer is useful when a function must modify a caller’s pointer, when building dynamic pointer tables, or when representing multi-level data structures.

13.12 const with Pointers — Read from the Identifier Outward

DeclarationWhat cannot be changed through this declaration
const int *pthe pointed-to int through p; p itself may point elsewhere
int *const p = &xthe pointer value p; *p may be modified
const int *const p = &xneither p nor the pointed-to int through p

13.13 NULL, Wild and Dangling Pointers

ProblemMeaning
Null pointerExplicit “points to no object” pointer value; test before dereference.
Wild/uninitialized pointerNo valid pointer value has been established.
Dangling pointerUsed to point to an object whose lifetime has ended or allocation was freed.

These are different states and require different prevention strategies.

13.14 Pointers and Strings

char text[] = "Hello";
char *p = text;
while (*p != '\0')
    putchar(*p++);

A string can be traversed with a pointer because its characters occupy contiguous array elements and the null terminator marks the logical end.

13.15 Pointers to Structures

struct Student { int id; double cgpa; };
struct Student s = {1, 8.5};
struct Student *ps = &s;
printf("%d", ps->id);

ps->id is equivalent to (*ps).id. Parentheses are required in the latter because member access binds more tightly than unary *.

13.16 Function Pointers

int compare(int a, int b) { return (a > b) - (a < b); }
int (*fp)(int, int) = compare;
int r = fp(3, 5);

Function pointers point to functions rather than objects. They have their own compatibility rules and are the basis of callbacks.

13.17 Pointer Safety Checklist

Is it initialized? → Does it point to a live compatible object? → Is the index/arithmetic within the array domain? → Is access permitted by const? → Will the object outlive the use?
  • Never dereference NULL.
  • Never use an uninitialized pointer.
  • After free, treat every alias to that allocation as potentially dangling.
  • Do not return addresses of automatic local objects.
  • Do not assume arbitrary integer values are usable object addresses.
  • Use sizes/counts alongside pointers to arrays/buffers.

13.18 Quick Revision

📌 Pointer → stores an address.

📌 &x → address of x.

📌 *p → value at address stored in p.

📌 Pointer arithmetic is commonly used with arrays.

📌 Arrays and pointers are closely related, but they are not identical concepts.

📌 Pointers allow functions to modify caller data when addresses are passed.

📌 malloc() → dynamic allocation.

📌 calloc() → zero-initialized allocation.

📌 realloc() → resize allocation.

📌 free() → release allocation.

📌 NULL pointer → intentionally points to no valid object.

13.21 Key Takeaway




        🎯 Remember this three-part rule:

        


&x → Address of x



p → Address stored in p



*p → Value at that address




        Once this becomes clear, pointers become
        much easier to understand.

    





INTERVIEW PREPARATION

🎤 Pointers — Interview Questions







1.
What is the difference between p, &x, and *p?





                If p points to x, &x is the address of x, p stores that address, and *p accesses the object at that address.
            







2.
What is a NULL pointer?





                A null pointer is a special pointer value that intentionally does not point to a valid object or function.
            







3.
What is a wild pointer?





                A wild pointer is an uninitialized pointer whose stored value is indeterminate. Dereferencing it causes undefined behavior.
            







4.
What is a dangling pointer?





                A dangling pointer still contains an address to storage whose lifetime has ended, such as memory that has already been freed.
            







5.
How are arrays and pointers related in C?





                In many expressions an array name is converted to a pointer to its first element, allowing pointer arithmetic such as arr + i and dereferencing such as *(arr + i).
            







6.
What does pointer arithmetic depend on?





                Adding or subtracting an integer from a pointer moves by elements of the pointed-to type, not by raw bytes.
            







7.
Why should realloc() commonly use a temporary pointer?





                If realloc() fails, it returns NULL while the original allocation remains valid. A temporary pointer prevents losing the original address.
            







8.
What is a function pointer?





                A function pointer stores the address of a compatible function and can be used to call that function indirectly.
            









PLACEMENT TIPS

💡 Pointers — Placement Tips


    

  • Always separate the three ideas: address, pointer value, and dereferenced object.
    • 

  • Initialize pointers before dereferencing them, and check dynamically allocated pointers against NULL.
    • 

  • For array-pointer questions, remember arr[i] and *(arr + i) refer to the same element.
    • 

  • Pointer arithmetic is scaled by the pointed-to type; p + 1 moves to the next element of that type.
    • 

  • After free(p), do not dereference p. Setting it to NULL can help avoid accidental reuse.
    • 

  • For realloc(), use a temporary pointer so the original allocation is not lost if resizing fails.
    •
