🔧 12. Functions

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

12.1 Why Functions Exist

A function gives a name and interface to a unit of behavior. Good functions reduce repetition, isolate responsibilities, improve testing and let programmers reason about one operation at a time.

Inputs (arguments) → Function contract/body → Return value and/or controlled side effects

12.2 Three Things Students Must Separate: Declaration, Definition and Call

int add(int, int);          /* declaration/prototype */

int main(void)
{
    int s = add(10, 20);   /* function call */
}

int add(int a, int b)      /* definition */
{
    return a + b;
}
TermPurpose
Declaration/prototypeTells compiler the function name, return type and parameter types.
DefinitionProvides the body/implementation.
CallEvaluates arguments and transfers control to the function according to the function type.

12.3 Function Type Is a Contract

The return type and parameter types describe how callers and the function communicate. A visible correct prototype lets the compiler diagnose many mismatched calls.

double power(double base, int exponent);

This says the function returns double and expects two parameters: a double and an int. Parameter names may be omitted in a prototype.

12.4 Parameters vs Arguments

int square(int x)  /* x is a parameter */
{
    return x * x;
}

int y = square(7); /* 7 is an argument */

An argument expression belongs to the caller. A parameter is the function’s local object initialized from the corresponding argument value, subject to the language’s parameter rules.

12.5 C Uses Pass-by-Value

void change(int x)
{
    x = 99;
}

int n = 10;
change(n); /* n remains 10 */

The parameter receives a value. Assigning to the parameter does not assign to the caller’s object. C does not have pass-by-reference parameters in the C++ sense.

12.6 How Pointers Let a Function Modify Caller-Owned Objects

void change(int *p)
{
    *p = 99;
}

int n = 10;
change(&n); /* pointer value is passed by value; *p accesses n */

Even here, C is still pass-by-value: the pointer value (address) is copied into parameter p. That copied pointer refers to the caller’s object, so dereferencing it can modify that object.

12.7 Return Values

double area(double r)
{
    return 3.14159 * r * r;
}

A non-void function communicates a result through return expression;. The expression is converted to the function return type. A void function returns no value.

12.8 The Four Beginner Function Forms

This classification is useful for beginners, but real design should focus on a clear contract rather than forcing every problem into a memorized category.

12.9 Scope and Lifetime of Local Objects

int f(void)
{
    int local = 10;
    return local;
}

int *bad(void)
{
    int local = 10;
    return &local; /* wrong: local lifetime ends when function returns */
}

A pointer can outlive the object it points to. Returning the address of an automatic local object creates a dangling pointer because that object’s lifetime has ended.

12.10 Array Parameters Are Adjusted to Pointers

void printArray(const int a[], size_t n)
{
    for (size_t i = 0; i < n; i++)
        printf("%d ", a[i]);
}

In a function parameter list, int a[] is adjusted to int *a. The function therefore needs a separate size or another protocol. sizeof a inside the function measures the pointer, not the caller’s whole array.

12.11 Recursion — A Function Solves a Smaller Version of the Same Problem

unsigned long long factorial(unsigned n)
{
    if (n <= 1)
        return 1;                 /* base case */
    return n * factorial(n - 1); /* progress */
}

Correct recursion needs a base case that stops further calls and a recursive step that moves toward that base case. Each active call has its own parameters/local automatic objects.

12.12 What Happens During a Function Call

caller evaluates arguments
        ↓
parameter values are established
        ↓
control enters function body
        ↓
local automatic objects exist for this call
        ↓
return value (if any) is produced
        ↓
local automatic lifetimes end
        ↓
control returns to caller

Actual machine stack/register details depend on the implementation and ABI; this conceptual call model is portable enough for learning C semantics.

12.13 Function Pointers

int add(int a, int b) { return a + b; }

int (*operation)(int, int) = add;
printf("%d\n", operation(2, 3));

A function pointer stores which compatible function to call. Read int (*operation)(int, int) as “operation is a pointer to a function taking two int arguments and returning int.”

12.14 Callbacks — Pass Behavior into Another Function

int apply(int a, int b, int (*op)(int, int))
{
    return op(a, b);
}

int result = apply(4, 5, add);

The caller supplies behavior as a function pointer. Standard-library examples include comparison callbacks used by functions such as qsort.

12.15 Variadic Functions

#include <stdarg.h>

int sumInts(int count, ...)
{
    va_list ap;
    int sum = 0;
    va_start(ap, count);
    for (int i = 0; i < count; i++)
        sum += va_arg(ap, int);
    va_end(ap);
    return sum;
}

A variadic function needs an external rule describing how many and what types of extra arguments exist. The language cannot automatically type-check the unnamed arguments the same way it checks ordinary prototyped parameters.

12.16 Designing Good Functions

  • Give the function one clear responsibility.
  • Use descriptive names and typed parameters.
  • Prefer return values for computed results when natural.
  • Use pointers when the function intentionally accesses caller-owned objects.
  • Document ownership if memory/resources cross the interface.
  • Keep hidden global-state dependencies to a minimum.
  • Validate preconditions or clearly document them.
  • Use const for pointer parameters that should not modify pointed-to data.

GCD Using Function

The greatest common divisor can be calculated efficiently using the Euclidean algorithm. 

int gcd(int a, int b)
{
    while(b != 0)
    {
        int temp = b;

        b = a % b;

        a = temp;
    }

    return a;
}

int main()
{
    int a, b;

    scanf("%d %d", &a, &b);

    printf("GCD = %d", gcd(a, b));

    return 0;
}

LCM Using Function

int gcd(int a, int b)
{
    while(b != 0)
    {
        int temp = b;

        b = a % b;

        a = temp;
    }

    return a;
}

long long lcm(int a, int b)
{
    if(a == 0 || b == 0)
        return 0;

    return (long long)a / gcd(a, b) * b;
}

int main()
{
    int a, b;

    scanf("%d %d", &a, &b);

    printf("LCM = %lld", lcm(a, b));

    return 0;
}

Recursive Factorial

long long factorial(int n)
{
    if(n <= 1)
        return 1;

int main()
{

Recursive Fibonacci

int fibonacci(int n)
{
    if(n == 0)
        return 0;

    if(n == 1)
        return 1;

    return fibonacci(n - 1)
         + fibonacci(n - 2);
}

int main()
{
    int n;

    scanf("%d", &n);

    printf("%d", fibonacci(n));

    return 0;
}
💡 This simple recursive Fibonacci implementation is useful for understanding recursion, but it is inefficient for large n.

🔍 Deeper understanding: Function interfaces, value passing and recursion

A prototype lets the compiler check argument and return types before a call. C passes every argument by value. Passing a pointer still copies the pointer value, but it allows the function to access the caller’s object. An automatic local object stops existing when its block ends, so returning its address creates a dangling pointer.

int divide(int numerator, int denominator, int *result)
{
    if (denominator == 0 || result == NULL)
        return 0;
    *result = numerator / denominator;
    return 1;
}

A recursive function needs both a base case and measurable progress toward it. Every active recursive call normally consumes stack space, so a logically terminating algorithm can still exhaust the stack for large input. Prefer an iterative form when recursion depth can grow with untrusted or very large input.

Common Function Mistakes

  • Calling a function before declaring it when no suitable declaration is visible.
  • Using the wrong return type.
  • Forgetting to return a value from a non-void function.
  • Passing the wrong number or type of arguments.
  • Forgetting that ordinary C arguments are passed by value.
  • Creating recursion without a proper base case.
  • Using too many global variables.
  • Giving one function too many unrelated responsibilities.
Reasoning trace:
&caller_object → copied pointer parameter → *parameter selects original object → assignment changes it
📘 Standard and portability note

Baseline: ISO C17. Nonlocal jumps and signal handlers impose special control-flow restrictions and belong in advanced systems programming.

🧩 Deep Dive — Function Contracts, Calls, Recursion and Callbacks

A Function Prototype Is a Type Contract

double average(int total, int count);

This tells the compiler the function name, return type, and parameter types before a call is checked. It is not merely “telling C that the function exists.” It lets the compiler verify that the call is compatible with the declared interface.

double result = average(95, 2);

Arguments are evaluated by the caller and converted as required for their parameter types. The parameters inside the function are new local objects initialized from the argument values.

C Uses Pass-by-Value — Even When Pointers Are Involved

void set_to_zero(int *p)
{
    *p = 0;
}

int x = 25;
set_to_zero(&x);

C passes a copy of the address stored in &x. The pointer parameter p itself is passed by value. Dereferencing that copied address allows the function to reach and modify the caller's object.

⚠️ “Call by reference” is not a separate C parameter mechanism

Some teaching material informally uses that phrase for pointer-based modification. The language mechanism remains pass-by-value; a pointer value is what gets copied.

Array Parameters Are Adjusted to Pointer Parameters

void print_values(const int a[], int n)

In a function parameter list, the declaration above is adjusted to a pointer parameter equivalent to:

void print_values(const int *a, int n)

That is why the function normally receives the length separately. Inside the function, sizeof a measures the pointer, not the caller's complete array.

What Happens During a Function Call?

main()
  x = 10
  y = 20
    │
    └── calls add(x, y)
             │
             ▼
        add(a=10, b=20)
        local result = 30
             │
             └── return 30
                    │
                    ▼
        main receives 30

Conceptually, each active call has its own parameters and automatic local variables. When the call finishes, those automatic local objects cease to exist. Therefore, returning the address of an automatic local variable produces an invalid pointer once the function has returned.

int *bad(void)
{
    int x = 10;
    return &x;   /* wrong: x's lifetime ends on return */
}

Recursion Needs Both Progress and a Base Case

unsigned long long factorial(unsigned int n)
{
    if (n <= 1)
        return 1;

    return n * factorial(n - 1);
}

The base case stops further calls. The recursive case must move toward it. If the state does not progress toward termination, recursion continues until resources are exhausted or another failure occurs.

📌 Recursion is not automatically faster

It can express naturally recursive structures and algorithms clearly, but each active call consumes resources. C does not guarantee tail-call optimization.

Function Pointers — Store Which Function to Call

int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }

int (*operation)(int, int) = add;
printf("%d\n", operation(8, 3));   /* 11 */

operation = sub;
printf("%d\n", operation(8, 3));   /* 5  */

Read int (*operation)(int, int) as: operation is a pointer to a function that receives two int arguments and returns int. The pointed-to function must have a compatible type.

Callbacks — Pass Behavior into Another Function

int apply(int x, int y, int (*fn)(int, int))
{
    return fn(x, y);
}

printf("%d\n", apply(6, 4, add));

apply does not need to know the details of addition. It receives a function to call. This technique is called a callback and is used by library algorithms, event systems, and configurable program designs.

Variadic Functions with <stdarg.h>

A variadic function accepts a fixed set of named parameters followed by .... Because the extra arguments do not carry an automatic runtime list of their types or count, the function needs a convention such as a count or format string.

#include <stdarg.h>

int sum_many(int count, ...)
{
    va_list args;
    int sum = 0;

    va_start(args, count);
    for (int i = 0; i < count; ++i)
        sum += va_arg(args, int);
    va_end(args);

    return sum;
}
int total = sum_many(4, 10, 20, 30, 40);

The caller and callee must agree on the promoted argument types. Asking va_arg for a type that is incompatible with what was actually passed leads to undefined behavior. This is why variadic interfaces require careful contracts.

INTERVIEW PREPARATION

🎤 Functions — Interview Questions







1.
What is the difference between a function declaration, definition, and call?





                A declaration tells the compiler the function's name, return type and parameters; a definition provides the body; a call transfers control to the function.
            







2.
What is the difference between parameters and arguments?





                Parameters are variables in the function definition. Arguments are the values or expressions supplied when the function is called.
            







3.
What does pass by value mean in C?





                The function receives copies of ordinary argument values, so changing those local parameter variables does not directly change the caller's scalar variables.
            







4.
Why are pointers used when a function must modify a caller variable?





                Passing the variable's address lets the function access and modify the original object through that pointer.
            







5.
What is recursion and what is a base case?





                Recursion is a function calling itself. A base case is the stopping condition that returns without making another recursive call.
            







6.
What is the difference between local and global variables?





                A local variable is declared inside a block or function and has block scope; a global variable is declared outside functions and has file scope.
            







7.
What is a static local variable?





                It has local scope but static storage duration, so its stored value persists across function calls.
            







8.
Why are small single-purpose functions useful?





                They improve readability, reuse, testing, maintenance and decomposition of larger problems.

  • Remember that ordinary scalar arguments are passed by value; use addresses when the original caller data must be modified.
    • 

  • Keep local variables local unless there is a genuine reason to use broader scope.
    • 

  • In interviews, explain both the function's logic and the cost of repeated calls, especially for recursive solutions such as naive Fibonacci.
    •
