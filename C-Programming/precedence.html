🧮 21. Operator Precedence & Associativity

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

21.1 Precedence, Associativity and Evaluation Order Are Three Different Concepts

ConceptQuestion it answers
PrecedenceWhich operator groups more tightly?
AssociativityWhen operators share precedence, how are they grouped?
Evaluation order / sequencingWhen are operand computations and side effects required to occur relative to each other?
Most common mistake

Students often think precedence means “the CPU evaluates this operator first.” Precedence is primarily a parsing/grouping rule.

21.3 Multiplication Before Addition

int x = 2 + 3 * 4;     /* 2 + (3 * 4) = 14 */
int y = (2 + 3) * 4;   /* 20 */

Parentheses explicitly change grouping and are often valuable even when you know the table, because they communicate intention to the reader.

21.4 Associativity Example: Assignment

a = b = c = 0;

Assignment operators associate right-to-left, so the grouping is a = (b = (c = 0)). This grouping still should not be generalized into a universal operand evaluation-order rule.

21.5 Associativity Example: Subtraction

int x = 20 - 5 - 2; /* (20 - 5) - 2 = 13 */

Additive operators associate left-to-right, so equal-precedence subtraction groups from the left.

21.6 Pointer Parsing Example: *p++

*p++

Postfix ++ has higher precedence than unary *, so the expression groups as *(p++): use the pointed-to value, then increment the pointer.

ExpressionGrouping / effect
*p++*(p++): postfix increment pointer
(*p)++postfix increment pointed-to object
*++pincrement pointer first, then dereference
++*pincrement pointed-to object and yield new value

21.7 Bitwise and Equality Precedence Trap

if (flags & MASK == 0)   /* groups unexpectedly */

if ((flags & MASK) == 0) /* intended bit test */

Equality operators bind more tightly than bitwise AND. Parenthesize bit tests when comparing the result.

21.8 Logical AND vs OR

if (a || b && c)

Logical AND binds more tightly than logical OR, so this groups as a || (b && c). Write parentheses when the business rule matters more than showcasing precedence knowledge.

21.9 Precedence Does Not Guarantee f() Runs Before g()

int x = f() + g();

The + operator groups its operands, but C does not generally require the left function call to be evaluated before the right one. If order matters, place operations in separate statements or use constructs with explicit sequencing rules.

21.10 Operators That Provide Sequencing

ConstructUseful guarantee
A && BA is evaluated first; B only if A is true.
A || BA is evaluated first; B only if A is false.
C ? A : BCondition first; exactly one selected branch expression is evaluated.
comma operator A, BA completes before B.

21.11 Comma Operator vs Comma Separator

x = (f(), g()); /* comma operator inside parentheses */
foo(a, b);       /* comma separates function arguments */

Not every comma token is the comma operator. Argument separators do not automatically impose left-to-right evaluation of function arguments.

21.12 Unsequenced Side Effects

i = i++ + ++i;          /* do not write this */
printf("%d %d", i++, i++); /* do not write this */

Such expressions can have undefined behavior because multiple modifications/accesses to the same scalar object are not appropriately sequenced. There is no portable “correct output” to memorize.

21.13 A Better Habit Than Memorizing the Whole Table

  • Know the major groups: postfix/unary, multiplicative/additive, comparisons, logical, conditional, assignment.
  • Use parentheses around mixed bitwise/comparison logic.
  • Use parentheses to communicate intent, not to create clever puzzles.
  • Separate side-effecting operations into statements when order matters.
  • Treat sequencing as a separate topic from precedence.

21.14 Guided Examples & Reinforcement

Now revisit the original worked examples, short explanations and visual examples. They are retained here to reinforce the concepts explained above.

What is Operator Precedence?

Operator precedence determines which operator is evaluated first when an expression contains multiple operators.

For example: 

int result = 10 + 5 * 2;

Multiplication has higher precedence than addition. Therefore:

5 × 2 = 10
10 + 10 = 20
Result = 20

What is Associativity?

When two operators have the same precedence, associativity determines the direction in which they are evaluated.

Most arithmetic, relational and logical operators have left-to-right associativity.

Unary, conditional and assignment operators contain important right-to-left cases. 

20 / 5 * 2

Division and multiplication have the same precedence, so they are evaluated from left to right:

20 / 5 = 4
4 × 2 = 8

Function calls, array subscripting and structure member access bind very tightly.

Pointer Dereference and Increment

Be careful with:

This is interpreted as:

Pointer Expression Example

int arr[] = {10, 20, 30};

int *p = arr;

printf("%d", *p++);

Because postfix ++ has higher precedence than unary *, this is equivalent to: 

*(p++)

The value printed is 10, and then p moves to the next array element.

10

Conditional Operator

The conditional operator has the form: 

condition ? expression1 : expression2

Example: 

int max = a > b ? a : b;

It is useful for simple conditional expressions.

Conditional Operator Associativity

The conditional operator associates from right to left. 

a ? b : c ? d : e

It is interpreted as: 

a ? b : (c ? d : e)
📌 Even though this is valid, nested conditional expressions should be written clearly with parentheses.

Comma Operator

The comma operator has the lowest precedence among the standard C operators. 

int x;

x = (10, 20, 30);

The expressions are evaluated from left to right and the value of the last expression is the result.

x = 30

Precedence Does NOT Determine Evaluation Order

⚠️ This is extremely important.

Operator precedence determines how an expression is grouped, but it does not generally tell you the order in which independent operands are evaluated.

For example, avoid writing expressions where the same scalar object is modified more than once without the required sequencing.

Dangerous Expressions

Avoid expressions such as: 

i = i++ + ++i;

The problem is not simply precedence. The expression modifies i multiple times without the required sequencing between those modifications.

Such expressions can result in undefined behavior and should not be used.

Write Clear Code Instead

Instead of writing a complicated expression: 

i = i++ + ++i;

use separate statements: 

i++;

i++;

result = i;
⭐ Good C programming prefers clear and well-defined expressions over clever but confusing expressions.

Best Practice: Use Parentheses

if((a & mask) == 0)
{
    printf("Bit is clear");
}

This is much clearer than relying on the reader to remember the exact precedence relationship between & and ==.

🔍 Deeper understanding: Precedence is not evaluation order

Precedence decides how tokens are grouped. Associativity resolves grouping between operators at the same precedence. Neither rule generally tells the compiler which operand must be evaluated first. For example, f() + g() groups as an addition, but C does not specify whether f or g is called first.

*p++       /* parsed as *(p++): use pointed value, then advance p */
(*p)++     /* increment the pointed-to object */
a & b == 0 /* parsed as a & (b == 0), often not intended */
(a & b) == 0 /* explicit and readable */

Parentheses are valuable even when the precedence table already gives the intended grouping. They document intent and protect maintenance changes. They still do not make unsequenced side effects safe.

Common Mistakes

  • Assuming expressions are always evaluated strictly from left to right.
  • Confusing precedence with evaluation order.
  • Forgetting that * / % have higher precedence than + -.
  • Confusing bitwise operators with logical operators.
  • Forgetting that assignment associates right-to-left.
  • Misreading *p++ as (*p)++.
  • Writing complicated expressions without parentheses.
  • Modifying the same scalar object multiple times without the required sequencing.
Reasoning trace:
postfix ++ groups with p → old p is dereferenced → p advances as a side effect

🧠 Deep Dive — Parsing, Associativity, Evaluation Order and Sequencing

Precedence Answers “How Is This Expression Grouped?”

a + b * c

Multiplication has higher precedence than addition, so the expression is parsed as:

a + (b * c)

This does not mean the language has stated a universal left-to-right execution order for all subexpressions.

Associativity Is Used When Operators Share a Precedence Level

a - b - c     /* (a - b) - c */
a = b = c     /* a = (b = c) */

Additive operators associate left-to-right. Assignment operators associate right-to-left. Associativity describes syntax grouping, not a promise about arbitrary operand evaluation order.

Sequencing Is a Separate Rule

f() + g()

The + operator tells us the values are added, but C does not generally require that f() be called before g(). If correctness depends on an order, write separate statements.

int left = f();
int right = g();
int result = left + right;
⚠️ Parentheses do not automatically create sequencing
(f()) + (g())

The parentheses make grouping explicit, but they do not by themselves require f to run before g.

Operators That Do Provide Useful Sequencing

Some operators have defined sequencing behavior that programmers intentionally rely on:

  • &&: evaluate the left operand first; evaluate the right only if needed.
  • ||: evaluate the left operand first; evaluate the right only if needed.
  • ?:: evaluate the condition, then exactly one of the second or third operands.
  • Comma operator: evaluate the left operand, then the right operand.
p != NULL && p->value > 0

This is safe because the right operand is not evaluated when p == NULL.

Comma Operator vs Comma Separator

x = (a = 1, a + 4);  /* comma operator: result is 5 */
printf("%d %d", a, b); /* commas separate function arguments */

The commas separating function arguments are not the comma operator and do not impose left-to-right argument evaluation.

Classic Pointer Parsing Example

ExpressionGroupingMeaning
*p++*(p++)Use object pointed to by old p, then increment pointer
(*p)++(*p)++Increment the pointed-to object
*++p*(++p)Increment pointer first, then dereference new pointer value
++*p++(*p)Increment the pointed-to object before producing the expression value

Bitwise and Equality Precedence Can Surprise Students

flags & MASK == 0

Equality binds more tightly than bitwise AND, so this groups as:

flags & (MASK == 0)

If the intention is to test the masked bits, write:

(flags & MASK) == 0

Avoid Expressions with Unsequenced Conflicting Side Effects

i = i++ + ++i;   /* undefined behavior */

The problem is not merely that the expression is “hard to read.” It modifies and accesses the same scalar object in a way that lacks the sequencing required by C. No precedence-table trick can make the result reliable.

✅ Practical rule

Use the precedence table to understand parsing, parentheses to communicate intended grouping, and separate statements whenever correctness depends on a particular evaluation order.

21.18 Key Takeaway




        🎯 Remember:

        


Precedence = grouping priority.



Associativity = direction for equal-precedence
        operators.



*, /, % come before + and -.



Arithmetic operators come before relational
        operators.



Relational operators come before equality operators.



Bitwise AND comes before XOR, which comes before OR.



&& comes before ||.



Assignment associates right-to-left.



Postfix operators such as p++ bind very tightly.



Precedence is not the same as evaluation order.



Use parentheses when an expression may be difficult
        to understand.







INTERVIEW PREPARATION

🎤 Operator Precedence & Associativity — Interview Questions







1.
What is operator precedence?




Operator precedence determines how operators in an expression are grouped when parentheses do not explicitly specify the grouping.







2.
What is associativity?




Associativity resolves grouping between operators at the same precedence level, such as left-to-right for * and / or right-to-left for assignment.







3.
Does precedence determine the runtime evaluation order of operands?




No. Precedence determines grouping, not the complete order in which operand computations or function calls are evaluated.







4.
Why does *p++ mean *(p++)?




Postfix ++ has higher precedence than unary *, so the pointer increment is grouped before dereferencing the old pointer value.







5.
Why is a = b = 20 valid?




Assignment associates right-to-left, so b = 20 is grouped first and its result is then assigned to a.







6.
How is 1 << 2 + 1 grouped?




Addition has higher precedence than shift, so it is grouped as 1 << (2 + 1).







7.
Why can 5 & 3 == 1 surprise programmers?




Equality has higher precedence than bitwise AND, so it is grouped as 5 & (3 == 1), not (5 & 3) == 1.







8.
What is the safest way to write complex expressions in production code?




Use clear intermediate variables or explicit parentheses instead of relying on readers to remember every precedence rule.









PLACEMENT TIPS

💡 Operator Precedence & Associativity — Placement Tips


    

  • Memorize the major operator groups, but use parentheses whenever a reader could reasonably misinterpret an expression.
    • 

  • When operators have the same precedence, check associativity: many arithmetic operators are left-to-right, while assignment is right-to-left.
    • 

  • Do not confuse grouping with evaluation order; precedence does not guarantee which operand runs first.
    • 

  • Be especially careful when mixing equality with bitwise operators, shifts with arithmetic, and pointer dereference with postfix increment.
    • 

  • Avoid expressions that modify the same scalar multiple times without proper sequencing; undefined behavior is not a precedence puzzle.
    • 

  • In interviews, show the grouping first with parentheses, then evaluate the grouped expression step by step.
    •
