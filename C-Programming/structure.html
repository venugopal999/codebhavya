🧱 2. Structure of a C Program

Before learning variables, data types, operators and control statements, you should understand how a C program is built. A C source file is not just a collection of random lines. Different parts have different jobs.

📚 How to Learn This Lesson

Do not memorize a list such as comments → header files → main() → functions without understanding what each part actually does.

Instead, learn to look at a C program and ask:

  • Which lines are comments?
  • Which lines are handled by the preprocessor?
  • Where does the program's main execution begin?
  • Which names are being declared?
  • Which lines actually perform operations?
  • Where are blocks created using { }?
  • Which functions belong to the programmer?
  • How does the source code eventually become an executable?

Once you can answer these questions, reading a new C program becomes much easier.

2.1 🧠 What Is the Structure of a C Program?

The structure of a C program means the way different C language elements are organized inside one or more source files.

A typical beginner-level C program may contain:

📝 Comments

Explain the program to human readers.

🔧 Preprocessor Directives

Give instructions to the preprocessor before compilation.

📦 Declarations

Introduce names, types, functions or other entities.

🚀 main()

Defines the program's entry point in a hosted C environment.

⚙️ Statements

Perform the actual operations of the program.

🧩 Functions

Organize reusable pieces of program logic.

2.2 🗺️ The Big Picture of a C Source File

A useful learning model is: 

C SOURCE FILE
     │
     ├── Comments
     │
     ├── Preprocessor directives
     │      ├── #include
     │      ├── #define
     │      └── conditional compilation
     │
     ├── Declarations / definitions
     │
     ├── main()
     │      ├── local declarations
     │      └── statements
     │
     └── Other function definitions
Important:

This diagram is a learning model for the common organization of a C program. It is not a rule saying every C source file must contain every section or must use exactly this order.

A very small program may contain only a preprocessor directive and main(). A large program may contain many source files, header files, declarations, structures and functions.

2.3 📝 Documentation and Comments

Comments are text written for humans. They help explain the purpose or reasoning behind code.

The compiler does not treat ordinary comments as executable C statements. 

// This program prints a message.

#include <stdio.h>

int main(void)
{
    printf("Hello, CodeBhavya!\n");
    return 0;
}

Single-line comments

// This is a single-line comment

Multi-line comments

/*
   This is a
   multi-line comment.
*/
Why are comments useful?
  • Explain purpose.
  • Document important decisions.
  • Make unfamiliar code easier to understand.
  • Help during maintenance and debugging.
Common confusion:

Comments are not a replacement for readable code. A comment such as // increment i above i++; usually adds little value.

Good comments explain why something is done when the reason is not obvious from the code itself.

2.4 🔧 Preprocessor Directives

A line such as: 

#include <stdio.h>

begins with # and is a preprocessing directive.

Preprocessing happens before the compiler performs the main compilation work. The C preprocessor handles facilities such as header inclusion, macro expansion and conditional compilation. :contentReference[oaicite:1]{index=1}

Example

#include <stdio.h>

#define MESSAGE "Hello"

int main(void)
{
    printf("%s\n", MESSAGE);
    return 0;
}

Here:

  • #include requests inclusion of a header.
  • #define creates a preprocessing macro.
  • main() belongs to the C language itself.
  • printf() is a library function being called.
Remember:

A preprocessing directive is not the same thing as a normal C statement. For example, #include does not end with a semicolon.

2.5 📦 Header Files and #include

Header files provide declarations and other information needed by source code.

For example: 

#include <stdio.h>

tells the preprocessing stage to include the contents available through the standard input/output header according to the implementation's header mechanism.

Code Purpose
#include <stdio.h> Provides declarations for standard I/O facilities.
#include <math.h> Provides declarations for mathematical functions.
#include <string.h> Provides declarations for string-handling functions.
#include <stdlib.h> Provides declarations for general utility functions.
Do not say:

"#include is a C function."

Correct idea:

#include is a preprocessing directive.

2.6 🚀 The main() Function

In a hosted C environment, program startup ultimately reaches the function named main.

A recommended beginner form is: 

int main(void)
{
    return 0;
}
Part Meaning
int The function returns an integer value.
main The special program entry function.
(void) Explicitly indicates that this form takes no arguments.
{ } Defines the function body.
return 0; Returns a successful status to the host environment.
Important distinction:

Do not teach void main() as the standard form for ordinary hosted C programs.

For this course, use: 

int main(void)

when the program does not use command-line arguments.

2.7 🧱 Function Body and Curly Braces

The curly braces define a block. 

int main(void)
{
    printf("Hello\n");
    return 0;
}

Everything between the opening { and closing } belongs to the body of main. 

int main(void)
│
├── {
│
│   statements
│   statements
│   statements
│
└── }

Blocks become extremely important later when we learn:

  • if statements
  • else
  • for loops
  • while loops
  • functions
  • scope
2.8 📦 Declarations Inside a Program

A declaration introduces information about an entity to the compiler.

For example: 

int age;

tells the compiler about an object named age having type int.

Inside a function, declarations commonly appear before the statements that use those objects in beginner C programs. 

int main(void)
{
    int age;

    age = 20;

    printf("%d\n", age);

    return 0;
}
Think of a declaration as an introduction.

Before the compiler can correctly understand how a name is being used, it often needs information about that name, such as its type.

2.9 ⚙️ Statements

A statement represents an instruction or action in a C program.

Example: 

printf("Hello\n");

return 0;

Many simple C statements end with a semicolon.

But remember:

Not every C construct ends with a semicolon.

For example, the declaration: 

int age;

does.

But the function definition: 

int main(void)
{
    return 0;
}

does not have a semicolon after the closing brace.

2.10 🧮 Expressions Inside Statements

An expression produces a value or performs an operation. 

5 + 3

is an expression. 

age = 20;

is a statement containing an assignment expression.

We will study expressions and operators in detail in later lessons. For now, recognize that statements and expressions are related but are not exactly the same concept.

2.11 📞 Function Calls

A function call asks a function to perform its defined work. 

printf("Hello, CodeBhavya!\n");

Here printf is being called.

Concept Example
Function name printf
Arguments "Hello, CodeBhavya!\n"
Function call printf(...);

Function calls will become much more important when we study user-defined functions.

2.12 ↩️ return and Program Status 
return 0;

returns the value 0 from main to the host environment.

In a normal hosted program, returning zero from main is conventionally used to indicate successful termination. 

main()
  │
  │ executes program
  │
  └── return 0;
          │
          ▼
    host environment
    receives status
Common confusion:

return 0; does not mean "print zero".

It means: return the integer value 0 from this function.

2.13 🧩 User-Defined Functions

As programs become larger, putting everything inside main() becomes difficult to manage.

C allows programmers to divide a program into functions. 

#include <stdio.h>

void greet(void)
{
    printf("Welcome to CodeBhavya!\n");
}

int main(void)
{
    greet();

    return 0;
}

Here:

  • greet() is a user-defined function.
  • main() calls greet().
  • The function contains its own block.
Why use functions?
  • Break large problems into smaller pieces.
  • Reduce repetition.
  • Improve readability.
  • Make testing easier.
  • Make programs easier to maintain.
2.14 🔍 Complete Anatomy of a C Program 
/* Program: Basic C Structure */

#include <stdio.h>

void greet(void);

int main(void)
{
    printf("Starting program...\n");

    greet();

    printf("Program finished.\n");

    return 0;
}

void greet(void)
{
    printf("Hello, CodeBhavya!\n");
}

Let's identify every part.

Part Code Role
Comment /* ... */ Human-readable documentation.
Preprocessor directive #include <stdio.h> Requests header inclusion during preprocessing.
Function declaration void greet(void); Introduces the function before its definition.
main() int main(void) Program entry function.
Function body { ... } Contains the function's code.
Function call greet(); Calls the user-defined function.
Return statement return 0; Returns status from main.
Function definition void greet(void) { ... } Provides the actual implementation.
2.15 🧠 Declaration vs Definition

This distinction becomes very important as your C programs become larger.

Function declaration

void greet(void);

This tells the compiler that a function named greet exists, takes no arguments in this form, and returns void.

Function definition

void greet(void)
{
    printf("Hello\n");
}

This provides the actual implementation of the function.

Declaration Definition
Introduces an entity. Provides the entity's complete implementation where required.
Example: void greet(void); Example: void greet(void) { ... }
Often ends with ; Function definition ends with its closing }
2.16 🔀 Why Do We Sometimes Write a Function Before main()?

Consider: 

#include <stdio.h>

void greet(void)
{
    printf("Hello!\n");
}

int main(void)
{
    greet();

    return 0;
}

The compiler has already encountered the definition of greet before reaching the call in main.

Another common organization is: 

#include <stdio.h>

void greet(void);

int main(void)
{
    greet();

    return 0;
}

void greet(void)
{
    printf("Hello!\n");
}

Here the declaration tells the compiler about greet before the call, while the definition appears later.

Important:

Do not memorize "all functions must come after main". That is not a C language rule.

What matters is that the compiler has the necessary declarations and that the program satisfies the language rules.

2.18 ✏️ Why Does C Use Semicolons?

Semicolons are commonly used to terminate C statements. 

int age;

age = 20;

printf("%d\n", age);

return 0;

Beginners often make one of two mistakes:

Missing semicolon

int age
age = 20;

Extra semicolon after a function definition

int main(void)
{
    return 0;
};

The second example illustrates why you should understand the difference between a function definition and a normal statement, rather than blindly adding semicolons everywhere.

2.19 📐 Whitespace and Indentation

C uses whitespace such as spaces, tabs and newlines in many places where it is not semantically significant.

Compare: 

int main(void)
{
    printf("Hello\n");
    return 0;
}

with: 

int main(void){printf("Hello\n");return 0;}

They can represent the same basic operations, but the first version is much easier for humans to read.

CodeBhavya rule:

Write code for both the compiler and the human reader.

Good indentation makes the block structure visible.

2.20 🔤 C Is Case-Sensitive

C distinguishes between uppercase and lowercase letters. 

age
Age
AGE

are three different identifiers.

Likewise: 

printf

is not the same identifier as: 

Printf
Common beginner mistake:

Writing Printf() instead of printf().

The C language and standard library names use exact spelling and capitalization.

2.21 🔬 Complete Program — Read It Like a Programmer 
/* Calculate and display a simple value */

#include <stdio.h>

int main(void)
{
    int number = 25;

    printf("Number = %d\n", number);

    return 0;
}

Step 1 — Comment

/* Calculate and display a simple value */

This communicates information to the human reader.

Step 2 — Header inclusion

#include <stdio.h>

The program uses printf, so it includes the appropriate standard input/output header.

Step 3 — main()

int main(void)

This defines the program's entry function.

Step 4 — Block

{
    ...
}

The braces delimit the body of main.

Step 5 — Declaration and initialization

int number = 25;

An integer object named number is declared and initialized with the value 25.

Step 6 — Function call

printf("Number = %d\n", number);

The program calls printf to produce formatted output.

Step 7 — Return

return 0;

The function returns zero to the host environment.

2.22 ⚠️ Common Structural Mistakes

Mistake 1 — Forgetting the header

int main(void)
{
    printf("Hello\n");
    return 0;
}

A modern compiler may diagnose the missing declaration for printf. Include the appropriate header when using the standard library function.

Correct:

#include <stdio.h>

int main(void)
{
    printf("Hello\n");
    return 0;
}

Mistake 2 — Wrong spelling

#include <studio.h>

The standard header is: 

#include <stdio.h>

Mistake 3 — Wrong capitalization

Printf("Hello");

Use: 

printf("Hello");

Mistake 4 — Missing braces

int main(void)
    printf("Hello\n");
    return 0;

The function body needs braces.

Mistake 5 — Missing semicolon

printf("Hello\n")

Should be: 

printf("Hello\n");

Mistake 6 — Treating #include as a function

#include(<stdio.h>)

This is incorrect.

Use: 

#include <stdio.h>

Mistake 7 — Using void main()

void main()
{
}

Do not use this as the standard beginner form for hosted C.

Use: 

int main(void)
{
    return 0;
}
2.23 🤔 Common Beginner Confusions

Confusion 1: Is #include part of C?

It is part of the C preprocessing language and is processed before the compiler's main translation of the C program.

Confusion 2: Is printf part of the C language syntax?

printf is a function provided by the C standard library. It is not a C keyword.

Confusion 3: Is main() a normal user-defined function?

It has the syntax of a function, but it has a special role: the program's startup environment invokes main in a hosted implementation.

Confusion 4: Must every C program have comments?

No. Comments are useful for humans but are not a mandatory component of every C source file.

Confusion 5: Must every C program have #include?

No. A program that does not require any included header can exist without an #include directive.

Confusion 6: Must main() always be the first function?

No. The organization of declarations and definitions depends on what the compiler needs to know at each point.

If an interviewer asks "What are the sections of a C program?", you can describe the common structure, but also mention that it is a conventional organizational model rather than a single mandatory template imposed on every C source file.

2.27 📝 Practice Questions

Question 1

What is the purpose of the main() function?

In a hosted C environment, main is the function through which program execution begins after program startup.

Question 2

Is #include a function?

No. #include is a preprocessing directive.

Question 3

Why is int main(void) preferred in this course for a program that takes no command-line arguments?

It clearly declares main as returning int and explicitly states that this form takes no arguments.

Question 4

What do the curly braces around main() represent?

They delimit the function body, which is a block containing the declarations and statements belonging to the function.

Question 5

What is the difference between a function declaration and a function definition?

A declaration introduces information about a function, while a definition provides its implementation.

Question 6

Does every C program need comments?

No. Comments are useful for human readers but are not mandatory in every C program.

Question 7

What is the role of a header file?

A header provides declarations and related information needed by source code. Standard headers provide interfaces to parts of the C standard library.

Question 8

Why does return 0; appear at the end of main() in many beginner programs?

It explicitly returns zero from main, conventionally indicating successful termination to the host environment.

Question 9

Is there one mandatory six-section template for every C source file?

No. The commonly taught sections are a useful organizational model. Actual C source files can be much simpler or more complex.

Question 10

Why is indentation important if the compiler can often ignore whitespace?

Indentation makes the program's structure easier for humans to read, understand, review and maintain.

INTERVIEW PREPARATION

🎤 C Program Structure — Interview Questions

1. What are the basic components of a C program?

A typical C program can contain comments, preprocessing directives, declarations and definitions, the main() function, statements and additional user-defined functions.

2. What is the role of main()?

In a hosted C environment, main is the function through which program execution begins.

3. What is a preprocessor directive?

It is an instruction handled by the C preprocessing stage. Examples include #include, #define and conditional compilation directives.

4. Is #include a statement?

No. It is a preprocessing directive.

5. Why is stdio.h included when using printf()?

The standard input/output header provides the declaration needed for the standard I/O facilities including printf.

6. What is the difference between declaration and definition?

A declaration introduces information about an entity. A definition provides the complete implementation or storage definition where applicable.

7. Why do we use return 0 in main()?

It returns zero from main, conventionally indicating successful program termination to the host environment.

8. Does every C program require #include?

No. It depends on whether the program needs declarations or other facilities supplied through headers.

9. Is void main() standard C?

It is not the standard hosted-program form taught in this course. Use int main(void) for a program with no command-line arguments.

10. Can a C program contain multiple functions?

Yes. A program can contain many functions. In larger programs, functions are commonly used to divide responsibilities into manageable pieces.

PLACEMENT TIPS

💼 Placement Tips — C Program Structure

Tip 1 — Know the difference between #include and linker.

#include belongs to preprocessing. Linking is a later build stage.

Tip 2 — Use int main(void).

It is a clear and standard form for a hosted C program with no command-line arguments.

Tip 3 — Don't memorize textbook sections blindly.

Interviewers may ask you to identify the actual role of comments, headers, declarations, definitions and functions.

Tip 4 — Understand declaration vs definition.

This distinction becomes especially important when programs are divided across multiple source and header files.

Tip 5 — Understand why headers are needed.

Do not memorize only "include stdio.h for printf". Understand that headers provide declarations and interfaces used by source code.

Tip 6 — Be ready for "find the error" questions.

Missing semicolons, incorrect header names, missing braces, wrong capitalization and invalid function declarations are common beginner-level interview exercises.
