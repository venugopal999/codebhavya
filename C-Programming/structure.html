🏗️ 2. Structure of a C Program

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

2.1 Complete Organizational Model of a C Program

A classroom C program is commonly explained using six logical sections. These sections help students understand where different kinds of declarations and statements belong. They are an organizational model: a small C program does not have to contain every section.

C Program
├── 1. Documentation Section
├── 2. Preprocessor / Linking Section
├── 3. Definition Section
├── 4. Global Declaration Section
├── 5. main() Function Section
│      ├── Local Declaration Section
│      └── Executable Section
└── 6. Subprogram / User-Defined Function Section

2.2 Documentation Section

The documentation section contains comments that explain the program to people. Typical information includes the program title, purpose, author, assumptions, algorithm notes, date and modification history. Comments are removed or ignored as program instructions; they do not execute.

/*
    Program : Simple Interest Calculator
    Purpose : Read principal, rate and time and compute interest
    Author  : CodeBhavya
*/

// A single-line comment
Comment formUse
// ...Single-line comment, available in modern C standards.
/* ... */Block comment; can span multiple lines.

2.3 Preprocessor / “Linking” Section

Traditional textbooks often call the header-inclusion area the link section. In modern terminology, directives such as #include are handled by the preprocessor. A header supplies declarations and macros needed by the source file; the actual linker works later when object files and libraries are combined.

#include <stdio.h>
#include <math.h>
Why ?

Functions such as printf and scanf are declared by the standard I/O header. Including the correct header lets the compiler check the call using the proper declaration.

2.4 Definition Section

In the traditional program-structure model, the definition section contains symbolic constants and macros used by later code.

#define PI 3.141592653589793
#define MAX_STUDENTS 60

#define PI ... does not create an ordinary C variable. It creates a preprocessing macro. A typed object such as const double pi = ...; is conceptually different and is explained in the Variables & Constants lesson.

2.5 Global Declaration Section

Declarations placed outside every function have file scope. This area can contain declarations or definitions of file-scope objects, function prototypes, type declarations and related information needed by multiple functions.

int totalStudents = 0;       /* file-scope object definition */

void displayTitle(void);      /* function declaration/prototype */
Declaration vs definition

A declaration introduces a name and its type. A definition provides the entity itself (for example, a function body or storage for an object), although C has detailed rules and some declarations can also be definitions.

2.6 main() Function Section

In a hosted C program, execution starts through the main function. A clear beginner form when no command-line arguments are needed is int main(void).

int main(void)
{
    /* local declarations */

    /* executable statements */

    return 0;
}

The braces create the function body, which is a block. Statements inside the block execute according to control flow, not simply because they appear somewhere in the source file.

2.7 Local Variable Declaration Section Inside main()

Objects declared inside the main block are local to that block unless a nested scope changes visibility. They are commonly used to store input values, intermediate results and output values.

int main(void)
{
    double radius;
    double area;
    /* ... */
}

In modern C, declarations do not have to be grouped only at the top of the function; they may appear later in a block. The traditional “local declaration section” remains a useful learning model.

2.8 Executable Section Inside main()

The executable section contains statements that perform the work: input, calculations, assignments, function calls, decisions, loops and output.

printf("Enter radius: ");
scanf("%lf", &radius);
area = PI * radius * radius;
printf("Area = %.2f\n", area);
Input → Processing → Output

The IPO model is useful for simple programs, but larger programs may repeat these stages, call functions, branch into different paths and manage resources.

2.9 Subprogram / User-Defined Function Section

A larger program is usually divided into functions. If a function definition appears after main, its declaration/prototype can appear earlier so the compiler knows the function type before a call is encountered.

void displayTitle(void);

int main(void)
{
    displayTitle();
    return 0;
}

void displayTitle(void)
{
    printf("Circle Area Calculator\n");
}
TermMeaning
Function declaration/prototypeIntroduces the function name, return type and parameter types.
Function definitionContains the actual function body.
Function callTransfers control to the function and supplies arguments, if any.

2.10 Complete Program Showing All Six Sections

/* 1. Documentation Section
   Program: Circle Area Calculator */

#include <stdio.h>              /* 2. Preprocessor section */

#define PI 3.14159              /* 3. Definition section */

void displayTitle(void);        /* 4. Global declaration section */

int main(void)                  /* 5. main function section */
{
    double radius;              /* local declaration */
    double area;

    displayTitle();             /* executable section */
    printf("Enter radius: ");
    scanf("%lf", &radius);
    area = PI * radius * radius;
    printf("Area = %.2f\n", area);

    return 0;
}

void displayTitle(void)         /* 6. subprogram section */
{
    printf("Circle Area Calculator\n");
}

2.11 Line-by-Line Execution vs Source Organization

The source file is organized into sections, but only executable statements run at runtime. A comment does not execute, an #include directive is handled before compilation, and a function definition does not execute merely because it appears earlier in the file. A function body executes only when control enters that function.

Translation time: comments/directives/declarations are processed
Runtime: main begins
   ↓
displayTitle() call → function body executes → returns
   ↓
input radius
   ↓
compute area
   ↓
print result
   ↓
return from main

2.12 How Source Becomes an Executable

Understanding structure is easier when students separate source organization from the build process.

Build stageWhat happens
PreprocessingExpands includes/macros and evaluates conditional directives.
CompilationChecks and translates C code.
Assembly/Object generationProduces machine-level object code.
LinkingResolves references among object files and libraries.
Loading/ExecutionOperating system starts the built program.

2.13 Which Sections Are Mandatory?

The six-section model is not a syntax rule. A tiny program may have no macros, no global declarations and no user-defined functions. A valid hosted program still needs an appropriate main definition, while header inclusion is needed only when declarations from that header are used.

Important

Do not teach students that every C program must physically contain six sections. Teach that the sections classify common parts of a program and make larger programs easier to organize.

2.14 Common Structural Mistakes and Why They Fail

  • Calling a function before the compiler has seen an appropriate declaration.
  • Writing executable statements at file scope where a declaration/definition is required.
  • Forgetting the semicolon after a declaration or expression statement.
  • Mismatched braces that change block structure.
  • Using a library function without including the header that declares it.
  • Placing a function definition inside another function; standard C does not support nested function definitions.

2.15 Mental Checklist Before Running a Program

QuestionWhat to inspect
Are required headers present?Preprocessor section
Are constants/types declared before use?Definition/global declaration area
Does main have a valid form?Main function header
Are local variables declared with suitable types?Local declaration area
Is input validated before use?Executable section
Are helper functions declared and defined consistently?Global declarations + function section
Are resources closed/freed?Executable cleanup paths

2.16 Quick Revision

📌 #include is a preprocessor directive.

📌 stdio.h provides declarations for standard input/output functions.

📌 main() is the entry point of a hosted C program.

📌 Statements generally end with ;.

📌 Curly braces { } define blocks of code.

📌 printf() is commonly used for output.

📌 scanf() is commonly used for formatted input.

📌 Most beginner programs can be understood using Input → Processing → Output.

2.17 Practice Questions

1. What is the purpose of #include?
#include is a preprocessor directive used to include a header file so that declarations needed by the program become available.
2. What is the role of stdio.h?
stdio.h is the standard input/output header file. It provides declarations for functions such as printf() and scanf().
3. What is the purpose of main()?
main() is the entry point of a hosted C program. Program execution begins from main().
4. Why are curly braces used?
Curly braces define a block of code and show where a function, loop, or conditional block begins and ends.
5. Why is a semicolon used in C?
A semicolon marks the end of most C statements.
6. What are comments?
Comments are notes written inside source code to improve readability and documentation. They are not executed as program statements.
7. What is the purpose of scanf()?
scanf() is commonly used to read formatted input from the user.
8. What is the purpose of printf()?
printf() is commonly used to display formatted output.
9. What does return 0 mean when returned from main()?
return 0; normally indicates successful termination of the program.
10. Explain the Input → Processing → Output model with an example.
For adding two numbers: Input = read a and b; Processing = sum = a + b; Output = display sum.

2.19 Key Takeaway

🎯 When solving a C programming problem, first identify:

1. What is the INPUT?
2. What PROCESSING is required?
3. What should be the OUTPUT?

This simple approach will become the foundation for solving more difficult programming problems.
