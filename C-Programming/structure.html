🏗️ 2. Structure of a C Program

🎓 How to Learn This Lesson

Do not try to memorize a C program line by line. Instead, learn what each part does and how all the parts work together.

By the end of this lesson, you should be able to look at almost any basic C program and identify:

  • Comments
  • Preprocessor directives
  • Header files
  • Functions
  • main()
  • Declarations
  • Statements
  • Expressions
  • Function calls
  • return
  • Opening and closing braces
2.1 What Is the Structure of a C Program?

A C program is a collection of instructions written using the C language. These instructions are organized into functions, declarations, expressions, statements and other language constructs.

A very small C program may contain only one function, while a large real-world program may contain hundreds or thousands of functions distributed across many source and header files.

💡 The Main Idea

A C program is not simply a collection of lines. Each part has a particular role.

For example:

  • #include → gives the preprocessor a directive
  • int main(void) → defines the program's main function
  • int age; → declares an object
  • age = 20; → performs an assignment
  • printf(...) → calls a function
  • return 0; → returns a value from main
2.2 Big Picture of a C Source File

A beginner-friendly way to visualize a C source file is: 

┌─────────────────────────────────────┐
│ Comments / Documentation            │
├─────────────────────────────────────┤

├─────────────────────────────────────┤
│ Declarations / Prototypes            │

⚠️ Important

This is a learning model, not a compulsory six-section rule of the C language.

C does not require every source file to contain all of these sections in exactly this order.

2.3 Documentation and Comments

Comments are text written for programmers. They help us explain what the program is doing.

Comments are ignored by the compiler when it translates the program.

Single-line comment

// This program calculates the sum

Multi-line comment

/*
   This program demonstrates
   the structure of a C program.
*/
Comment type Syntax Typical use
Single-line // ... Short explanation
Multi-line /* ... */ Longer documentation
💡 Tip: Write comments to explain why something is done when the code itself does not make the reason obvious.
2.4 Preprocessor Directives

Lines beginning with # are commonly used for preprocessor directives.

Example:

#include <stdio.h>

The preprocessor handles such directives before the compiler performs the normal C translation process.

Common examples

#include <stdio.h>
#define PI 3.14159

⚠️ Common Confusion

#include is not a function.

It is a preprocessor directive.

Also, #include itself does not perform library linking. Linking happens later in the build process.

2.5 Header Files and #include

Header files contain declarations and other information that can be shared with source files.

For example: 

#include <stdio.h>

gives the compiler the declarations associated with the standard input/output facilities provided through stdio.h, including the declaration of printf().

Part Role
Header file Provides declarations and related interface information
Library implementation Provides the actual implementation of library facilities
Linker Resolves external references during linking

🎯 Remember

#include <stdio.h> does not mean "run stdio.h".

It tells the preprocessor to make the requested header contents available to the source file.

2.6 The main() Function

In a hosted C environment, main is the designated entry function of the program.

A preferred form for a program that does not use command line arguments is: 

int main(void)
{
    return 0;
}

int

Specifies that main returns an integer value.

main

Identifies the program's main function.

(void)

Explicitly states that this function takes no parameters.

⚠️ Common Beginner Confusion

Avoid teaching void main() as the standard form of a hosted C program.

Prefer int main(void) for a program with no command-line arguments.

2.7 Function Body and Curly Braces

The curly braces { and } define a block. 

int main(void)
{
    printf("Hello");
    return 0;
}

Everything between the braces belongs to the body of main. 

int main(void)
{

    │      Function Body           │
    │                              │
    │  statements                  │

    │  function calls              │

}
2.8 Declarations Inside a Program

A declaration introduces information about an identifier to the compiler.

Example:

int age;
float salary;
char grade;

These declarations tell C about the type of each object.

Declaration Meaning
int age; An integer object named age
float salary; A floating-point object named salary
char grade; A character object named grade
2.9 Statements

A statement represents an action that the program performs as execution proceeds.

Examples:

age = 20;

printf("%d", age);

return 0;

Many C statements end with a semicolon.

⚠️ Important

Do not memorize the rule as "every C line needs a semicolon."

The semicolon terminates particular statements, such as expression statements and declarations. Constructs such as if, while and function definitions have their own syntax.

2.10 Expressions Inside Statements

An expression produces a value or performs an operation.

Example:

a + b
x * 10
age = 25
count++

An expression can appear inside a larger statement. 

sum = a + b;

Here:

  • a + b is an expression.
  • The complete sum = a + b; is an expression statement.
2.11 Function Calls

A function call asks a function to perform its operation. 

printf("Hello");

In this example, printf() is called with one argument: the string literal.

Another example: 

int result = add(10, 20);

Here the program calls the user-defined function add().

2.12 return and Program Status

The return statement exits a function and can provide a value to the caller. 

return 0;

When used in main, this returns an integer termination status to the host environment.

⚠️ Common Confusion

return 0; does not print zero on the screen.

It returns the value 0 from main.

2.13 User-Defined Functions

Large programs should not place all logic inside main().

We can divide the program into smaller functions. 

#include <stdio.h>

int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    int result;

    result = add(10, 20);

    printf("%d", result);

    return 0;
}

Here the program contains two function definitions:

  • add()
  • main()

💡 Why use functions?

  • Break large problems into smaller problems.
  • Reuse logic.
  • Improve readability.
  • Make testing easier.
  • Make maintenance easier.
2.14 Complete Anatomy of a C Program

Now combine the major concepts into one complete program. 

/* Program to calculate the sum of two numbers */

#include <stdio.h>

int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    int x;
    int y;
    int result;

    printf("Enter two numbers: ");
    scanf("%d %d", &x, &y);

    result = add(x, y);

    printf("Sum = %d\n", result);

    return 0;
}
Part Example Purpose
Comment /* ... */ Documentation
Preprocessor directive #include <stdio.h> Include header information
Function definition int add(...) Define reusable logic
Declaration int result; Declare an object
Input scanf(...) Read values
Function call add(x, y) Execute another function
Output printf(...) Display information
Return statement return 0; Finish main with a status
2.15 Declaration vs Definition

This distinction becomes extremely important as C programs become larger.

Declaration

A declaration tells the compiler about an identifier and its type or interface. 

int add(int, int);

Definition

A definition provides the actual implementation or creates the entity being declared. 

int add(int a, int b)
{
    return a + b;
}
Declaration Definition
Describes an entity Provides the entity's implementation or storage
int add(int, int); int add(int a, int b) { ... }
2.16 Why Function Definitions May Appear Before or After main

A function can be defined before main: 

int add(int a, int b)
{
    return a + b;
}

int main(void)
{
    printf("%d", add(2, 3));
    return 0;
}

It can also be defined after main, provided that the compiler has seen an appropriate declaration before the call. 

#include <stdio.h>

int add(int, int);

int main(void)
{
    printf("%d", add(2, 3));
    return 0;
}

int add(int a, int b)
{
    return a + b;
}

🎯 Key Idea

The compiler needs to know enough about a function before it is used. A function prototype can provide that information.

2.18 Why C Uses Semicolons

The semicolon is an important token in C syntax.

For example: 

int age = 20;
printf("%d", age);
return 0;

These are statements that are terminated with semicolons.

⚠️ Common Mistake

printf("Hello")

The statement is incomplete because its terminating semicolon is missing. 

printf("Hello");

This is the correct form.

2.19 Whitespace and Indentation

Spaces, tabs and line breaks make source code easier for humans to read. They generally do not change the meaning of ordinary C expressions when used appropriately. 

int main(void)
{
    printf("Hello");
    return 0;
}

Compare it with: 

int main(void){printf("Hello");return 0;}

Both can represent the same basic program, but the first version is much easier to read and maintain.

💡 Professional habit: Use consistent indentation and meaningful spacing.
2.20 C Is Case-Sensitive

C distinguishes between uppercase and lowercase letters. 

int age;

int Age;

int AGE;

These are different identifiers.

Similarly: 

printf()

is not the same as: 

Printf()

🎯 Remember

C is case-sensitive. Small and capital letters matter.

2.21 Complete Program — Read It Like a Programmer 
#include <stdio.h>

int square(int number)
{
    return number * number;
}

int main(void)
{
    int n;
    int result;

    printf("Enter a number: ");
    scanf("%d", &n);

    result = square(n);

    printf("Square = %d\n", result);

    return 0;
}

🔎 Read it step by step

  1. #include <stdio.h> makes standard I/O declarations available.
  2. square() is a user-defined function.
  3. main() is the hosted program entry function.
  4. n stores the input.
  5. scanf() reads the input.
  6. square(n) calls another function.
  7. result stores the returned value.
  8. printf() displays the result.
  9. return 0; ends main with a success status.
2.22 Common Structural Mistakes
Mistake Problem Correct idea
Missing #include Required declarations may be unavailable Include the appropriate header
Missing { Function/block structure becomes invalid Match opening and closing braces
Missing ; Statement syntax becomes invalid Terminate statements where required
Using Printf() C is case-sensitive Use printf()
Writing void main() Not the preferred standard hosted form Use int main(void)
Forgetting function declaration Function may be used without required prior information Declare it before use when needed
Thinking return 0; prints 0 Misunderstands return status It returns a value from main
2.23 Common Beginner Confusions

❓ Is #include a function?

No. It is a preprocessor directive.

❓ Is main() a keyword?

No. main is the name of the designated entry function in a hosted C program.

❓ Is printf() a keyword?

No. printf() is a standard library function.

❓ Is return a function?

No. return is a C keyword used by the return statement.

❓ Are braces only for functions?

No. Braces are also used to form blocks for constructs such as if, for and while.

2.24 Textbook Structure vs Actual C

You may see textbooks describe a C program using sections such as:

  1. Documentation section
  2. Link section
  3. Definition section
  4. Global declaration section
  5. main() section
  6. Subprogram section

This is a useful teaching model, but it should not be treated as a compulsory syntax rule.

🎯 Better Understanding

Real C programs can have many different structures. The language standard does not require every program to follow the traditional six-section textbook arrangement.

Learn the purpose of each component instead of memorizing a fixed template.

2.27 Practice Questions

🧠 Test Your Understanding

1. What is the purpose of #include?

It is a preprocessor directive that makes the contents or declarations from the specified header available to the source file.

2. What is the purpose of main()?

In a hosted C program, main is the designated program entry function.

3. What is the difference between a declaration and a definition?

A declaration provides information about an entity, while a definition provides the entity's implementation or storage as appropriate.

4. Why is return 0; used in main()?

It returns the integer value 0 from main as the program's termination status.

5. Is printf() a keyword?

No. printf() is a standard library function.

6. Why are curly braces important?

Curly braces define blocks and group the declarations and statements belonging to a function or control-flow construct.

7. Is the traditional "six sections of a C program" a compulsory rule?

No. It is a useful textbook organization model, not a compulsory structure imposed on every C source file.

🎤 Structure of C Program — Interview Questions

1. What is the basic structure of a C program?

A C program can contain comments, preprocessor directives, declarations, function definitions, main(), statements, expressions and other program components. There is no single compulsory textbook layout for every C program.

2. What is the role of main()?

In a hosted C program, main is the designated entry function.

3. Is #include part of the C language syntax?

#include is a preprocessing directive. It is handled by the preprocessor before normal C translation.

4. What is the difference between a function declaration and definition?

A declaration provides information about the function, while the definition supplies its actual implementation.

5. Why is int main(void) preferred?

It clearly specifies that main returns an integer and takes no parameters.

6. What is the purpose of a header file?

A header provides declarations and related interface information that can be shared with source files.

7. What does return 0; mean in main()?

It returns the integer value zero from main as the program's termination status.

💡 Structure of C Program — Placement Tips

  • Be able to explain the purpose of #include without saying that it "links" the library.
  • Know the difference between a declaration and a definition.
  • Understand why main() is special in a hosted C program.
  • Be comfortable explaining int main(void).
  • Remember that C is case-sensitive.
  • Know why missing semicolons and braces produce translation errors.
  • Understand the basic sequence: preprocessing → compilation → assembly → linking → execution.
  • Do not memorize the traditional "six sections" as a compulsory language rule.
