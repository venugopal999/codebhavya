🧠 17. Dynamic Memory Allocation

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

17.1 Why Dynamic Memory Exists

Automatic arrays require a size/lifetime tied to block execution. Dynamic allocation lets a program request storage during runtime and keep that allocation alive until it is explicitly released.

request bytes → receive pointer or NULL → use within bounds → release exactly once

17.2 Storage Duration vs “Stack/Heap” Vocabulary

The C language specifies storage durations and allocation functions, while “stack” and “heap” are common implementation terms. Automatic local objects are commonly implemented using a stack-like region; malloc-family allocations commonly come from a heap-like allocator. Teach the language lifetime rules first, then the implementation model.

17.3 malloc() — Allocate Uninitialized Storage

int *a = malloc(n * sizeof *a);
if (a == NULL)
{
    /* allocation failed */
}

malloc returns a suitably aligned pointer to at least the requested number of bytes or a null pointer on failure. The allocated bytes have indeterminate contents until the program stores meaningful values.

17.4 Why sizeof *ptr Is a Strong Pattern

int *a = malloc(n * sizeof *a);

Using sizeof *a automatically follows the pointed-to type. If the declaration later changes from int * to another pointer type, the allocation expression is less likely to become inconsistent.

17.5 Protect the Size Calculation from Overflow

if (n > SIZE_MAX / sizeof *a)
{
    /* requested element count cannot be represented as byte count */
}
else
{
    a = malloc(n * sizeof *a);
}

Multiplication can overflow before malloc sees the size. A wrapped smaller request followed by writes for n elements can become a serious buffer overflow.

17.6 calloc() — Count × Element Size with Zeroed Bytes

int *a = calloc(n, sizeof *a);

calloc allocates space for an array-like count of elements and initializes all bytes to zero. Zero bytes correspond to numeric zero for common integer representations, but “all-bits-zero” should not be generalized carelessly to every possible C object representation or conceptual invariant.

17.7 realloc() — Resize While Preserving Existing Prefix Data

int *tmp = realloc(a, newCount * sizeof *a);
if (tmp != NULL)
{
    a = tmp;
    count = newCount;
}
else
{
    /* original a is still valid */
}

realloc may keep the allocation at the same address or move it. On success, the old pointer value must no longer be used to access the old allocation; on ordinary failure for a nonzero request, the original allocation remains valid.

17.8 Why a Temporary Pointer Matters with realloc

a = realloc(a, newSize); /* dangerous if failure would overwrite the only pointer */

Assigning directly to the only owner can lose the original pointer when realloc returns NULL, creating a memory leak. Save the result in a temporary pointer until success is known.

17.9 free() Ends the Allocation Lifetime

free(a);
a = NULL; /* useful for this variable, but aliases may still dangle */

free releases an allocation obtained from the compatible allocation family. After release, accessing the former object through any pointer is invalid. Setting one pointer variable to NULL does not magically update other aliases.

17.10 Memory Leak, Dangling Pointer, Double Free and Use-After-Free

17.11 Ownership — Decide Who Must free()

Dynamic-memory interfaces become much clearer when each allocation has an ownership rule. The owner is responsible for eventually releasing it, or explicitly transferring ownership to another component.

Interface styleOwnership idea
Function returns newly allocated pointerCaller usually becomes owner.
Function receives borrowed pointerCaller retains ownership; callee must not free unless contract says so.
Function takes T ** and replaces allocationContract should state whether old allocation is freed/transferred.

17.12 Dynamic Arrays

size_t n;
scanf("%zu", &n);

int *a = malloc(n * sizeof *a);
if (a == NULL && n != 0)
    return 1;

for (size_t i = 0; i < n; i++)
    a[i] = 0;

free(a);

Pointer subscripting works because the allocated block can be treated as an array of the requested element type when used according to the allocation/alignment/lifetime rules.

17.13 Dynamic Strings

size_t len = strlen(src);
char *copy = malloc(len + 1);
if (copy != NULL)
    memcpy(copy, src, len + 1);

The +1 reserves space for the terminating null character. String allocation bugs often come from forgetting that terminator or using the wrong source length.

17.14 Dynamic Structures

struct Student *s = malloc(sizeof *s);
if (s != NULL)
{
    s->id = 101;
    s->cgpa = 8.9;
}
free(s);

The arrow operator is natural when a structure object lives in dynamically allocated storage.

17.15 Dynamic 2D Data: Contiguous vs Row-Pointer Designs

/* contiguous R x C block */
int *m = malloc(rows * cols * sizeof *m);
/* element (r,c): m[r * cols + c] */

A contiguous block gives one allocation and predictable row-major layout. An array of row pointers supports separately allocated rows and potentially jagged lengths but requires more allocations and cleanup steps.

17.16 Cleanup on Failure

FILE *fp = fopen(name, "r");
if (!fp) return 1;

char *buf = malloc(size);
if (!buf)
{
    fclose(fp);
    return 1;
}

/* work */
free(buf);
fclose(fp);

Every successfully acquired resource needs a corresponding release on every path that leaves its ownership scope. This is why centralized cleanup patterns are common in C.

17.17 Dynamic-Memory Checklist

  • Is the byte-count calculation overflow-safe?
  • Is the returned pointer checked?
  • Is every access inside the allocated element count?
  • Who owns the allocation?
  • Can realloc failure preserve the original pointer?
  • Is every allocation released exactly once?
  • Are aliases prevented from being used after release?

Dynamic Memory Allocation allows a C program to request memory during program execution.

Unlike fixed-size arrays, dynamically allocated memory can be requested according to the actual requirements of the program.

malloc()

malloc() allocates a block of uninitialized memory of the requested size. 

#include <stdlib.h>

int *ptr;

ptr = malloc(5 * sizeof *ptr);

Here, memory is requested for five integers.

Example Using malloc()

#include <stdio.h>
#include <stdlib.h>

int main()
{
    int *ptr;

    ptr = malloc(5 * sizeof *ptr);

    if(ptr == NULL)
    {
        printf("Memory allocation failed");
        return 1;
    }

    for(int i = 0; i < 5; i++)
    {
        ptr[i] = (i + 1) * 10;
    }

    for(int i = 0; i < 5; i++)
    {
        printf("%d ", ptr[i]);
    }

    free(ptr);

    return 0;
}

Does malloc() Initialize Memory?

No. The bytes returned by malloc() have indeterminate values until your program writes appropriate values into them. 

int *ptr = malloc(5 * sizeof *ptr);

Do not assume the allocated integers are initialized to zero.

calloc()

calloc() allocates memory for multiple elements and initializes the allocated bytes to zero. 

int *ptr;

ptr = calloc(5, sizeof *ptr);

The first argument specifies the number of elements. The second specifies the size of each element.

Example Using calloc()

#include <stdio.h>
#include <stdlib.h>

int main()
{
    int *ptr;

    ptr = calloc(5, sizeof *ptr);

    if(ptr == NULL)
    {
        printf("Memory allocation failed");
        return 1;
    }

    for(int i = 0; i < 5; i++)
    {
        printf("%d ", ptr[i]);
    }

    free(ptr);

    return 0;
}

realloc()

realloc() changes the size of a previously allocated memory block. 

ptr = realloc(ptr, 10 * sizeof *ptr);

The block may be moved to a different memory location. Therefore, use the pointer returned by realloc().

Example Using realloc()

#include <stdio.h>
#include <stdlib.h>

int main()
{
    int *ptr;

    ptr = malloc(3 * sizeof *ptr);

    if(ptr == NULL)
        return 1;

    for(int i = 0; i < 3; i++)
    {
        ptr[i] = (i + 1) * 10;
    }

    int *temp = realloc(ptr, 5 * sizeof *ptr);

    if(temp == NULL)
    {
        free(ptr);
        return 1;
    }

    ptr = temp;

    ptr[3] = 40;
    ptr[4] = 50;

    for(int i = 0; i < 5; i++)
    {
        printf("%d ", ptr[i]);
    }

    free(ptr);

    return 0;
}
10 20 30 40 50

Safe Use of realloc()

Do not directly overwrite your only pointer with realloc() if you need to handle allocation failure safely.

Prefer a temporary pointer: 

int *temp;

temp = realloc(ptr, new_size);

if(temp != NULL)
{
    ptr = temp;
}
else
{
    /* Original ptr is still valid */
}

free()

free() releases dynamically allocated memory back to the implementation. 

free(ptr);

After freeing memory, the pointer value becomes indeterminate. If you keep the pointer variable, assigning NULL to it can help prevent accidental reuse. 

free(ptr);
ptr = NULL;

Checking for NULL

Dynamic allocation functions return a null pointer if the allocation fails. 

int *ptr = malloc(100 * sizeof *ptr);

if(ptr == NULL)
{
    printf("Memory allocation failed");
    return 1;
}
📌 Always check the result of malloc(), calloc() and realloc() before using the allocated memory.

Dynamic Structure

Structures can also be allocated dynamically. 

#include <stdio.h>
#include <stdlib.h>

struct Student
{
    int roll;
    float marks;
};

int main()
{
    struct Student *s;

    s = malloc(sizeof *s);

    if(s == NULL)
        return 1;

    s->roll = 101;
    s->marks = 85.5;

    printf("Roll = %d\n", s->roll);
    printf("Marks = %.2f\n", s->marks);

    free(s);

    return 0;
}

Accessing Dynamic Structures

When a pointer points to a structure, the -> operator is used to access its members. 

s->roll = 101;
s->marks = 85.5;

This is equivalent to: 

(*s).roll = 101;
(*s).marks = 85.5;

Dynamic Array of Structures

#include <stdio.h>
#include <stdlib.h>

struct Student
{
    int roll;
    float marks;
};

int main()
{
    int n;

    scanf("%d", &n);

    struct Student *students =
        malloc(n * sizeof *students);

    if(students == NULL)
        return 1;

    for(int i = 0; i < n; i++)
    {
        scanf("%d %f",
              &students[i].roll,

    {
        printf("%d %.2f\n",
               students[i].roll,
               students[i].marks);
    }

    free(students);

    return 0;
}

Dynamic 2D Array

A two-dimensional array can also be allocated dynamically. One simple method is to allocate one contiguous block. 

#include <stdio.h>
#include <stdlib.h>

int main()
{
    int rows = 3;
    int cols = 4;

    int *matrix =
        malloc(rows * cols * sizeof *matrix);

    if(matrix == NULL)
        return 1;

    for(int i = 0; i < rows; i++)
    {
        for(int j = 0; j < cols; j++)
        {
            matrix[i * cols + j] = i + j;
        }
    }

    for(int i = 0; i < rows; i++)
    {
        for(int j = 0; j < cols; j++)
        {
            printf("%d ", matrix[i * cols + j]);
        }

        printf("\n");
    }

    free(matrix);

    return 0;
}

Memory Leak

A memory leak occurs when dynamically allocated memory is no longer reachable by the program and has not been released. 

int *ptr = malloc(100 * sizeof *ptr);

/* ptr is lost without calling free() */

ptr = NULL;
⚠️ If dynamically allocated memory is no longer needed, release it using free().

Dangling Pointer

A dangling pointer is a pointer that refers to memory whose lifetime has ended or that has already been freed. 

int *ptr = malloc(sizeof *ptr);

*ptr = 10;

free(ptr);

/* ptr should not be dereferenced here */

A common defensive practice is: 

free(ptr);
ptr = NULL;

Double Free

Calling free() more than once on the same allocation is invalid. 

free(ptr);

/* Do not do this again: */
free(ptr);

Setting the pointer to NULL after freeing can help avoid accidental repeated freeing, because free(NULL) has no effect.

Use-After-Free

Accessing memory after it has been released is invalid. 

free(ptr);

/* Invalid */
printf("%d", *ptr);
⚠️ Never read from or write through a pointer after its allocated object has been freed.

Using sizeof() Correctly

Prefer using the pointed-to type when allocating memory. 

int *ptr;

ptr = malloc(10 * sizeof *ptr);

This style is easier to maintain if the pointer type changes later.

🔍 Deeper understanding: Ownership and failure-safe allocation

Allocated storage has no automatic owner in C; the program must define who is responsible for releasing it. malloc returns uninitialized storage, while calloc initializes all bytes to zero. Zero bytes produce valid zero values for integer types, but code should not assume that every possible C type has an all-bits-zero representation in every historical implementation.

/* SIZE_MAX is declared by <stdint.h>. */
if (count != 0 && count > SIZE_MAX / sizeof *items) {
    /* requested byte count would overflow */
    return NULL;
}
int *items = malloc(count * sizeof *items);

Use a temporary pointer with realloc:

/* Check new_count against SIZE_MAX / sizeof *items first. */
int *larger = realloc(items, new_count * sizeof *items);
if (larger != NULL) {
    items = larger;
}

If realloc fails, the original allocation is still valid. Assigning directly to items would lose that address and leak memory. After free(items), every alias to the allocation becomes dangling; setting one pointer to NULL does not repair the others.

Common Dynamic Memory Mistakes

  • Forgetting to check whether allocation returned NULL.
  • Forgetting to call free().
  • Accessing memory after free().
  • Freeing the same allocation twice.
  • Writing beyond the allocated block.
  • Losing the only pointer to allocated memory.
  • Using the wrong size in malloc() or calloc().
  • Overwriting the original pointer with realloc() without considering allocation failure.
Reasoning trace:
old owner → realloc request → success: adopt returned pointer | failure: keep old pointer → eventually free once
📘 Standard and portability note

Check multiplication overflow before allocation. In C, do not cast the result of malloc.

Correct Answer: B

Commit the new pointer only after realloc succeeds.

🧠 Deep Dive — Allocation Size, Object Lifetime, Ownership and Failure Paths

Allocation Gives You Bytes — Your Program Gives Those Bytes Meaning

int *a = malloc(10 * sizeof *a);

If allocation succeeds, the returned pointer designates storage large enough for ten int objects. The expression sizeof *a is preferred over repeating sizeof(int) because it stays correct if the pointer's pointed-to type later changes.

Always Protect the Size Calculation

The multiplication used to calculate allocation size is itself integer arithmetic. If count * sizeof *a overflows size_t, the allocator may receive a much smaller number of bytes than intended.

#include <stdint.h>

if (count > SIZE_MAX / sizeof *a) {
    /* requested size cannot be represented */
    return NULL;
}

a = malloc(count * sizeof *a);
💡 Why check before calling malloc?

malloc sees only the final byte count. It cannot know that an earlier multiplication wrapped and that you intended a larger allocation.

calloc Zeroes Bytes — Understand What That Means

int *a = calloc(count, sizeof *a);

calloc allocates enough storage for count elements and initializes the allocated bytes to zero. For the ordinary integer objects students normally use, this yields zero values. The precise language rule is byte initialization, so avoid teaching calloc as a universal “construct every C type with its semantic zero value” operation.

realloc May Move the Allocation

int *temp = realloc(a, new_count * sizeof *a);
if (temp != NULL) {
    a = temp;
}

On success, the returned pointer is the pointer that must be used for the resized allocation; the old pointer value must not continue to be used unless it is the same returned value. The data in the common old/new portion is preserved. Newly added bytes are not automatically initialized.

Common mistake
a = realloc(a, new_size);

If allocation fails, realloc returns NULL and the original allocation remains allocated. Direct assignment would lose the only pointer to it. Use a temporary pointer when failure must preserve the old object.

Zero-Size Requests Are Not a Good Ownership Interface

The standard permits special behavior for zero-size allocation requests. A call can return a null pointer or a non-null pointer value that must not be used to access an object. Code is clearer when it handles a logical element count of zero explicitly instead of depending on allocator-specific zero-size behavior.

Ownership — Decide Who Must Call free

C has no garbage collector that automatically discovers whether allocated storage is still needed. A robust program establishes an ownership rule.

char *make_name(void);        /* caller owns returned allocation */
void destroy_name(char *p);   /* releases it */
Ownership lifecycle
allocate → initialize → use → transfer/share carefully → free exactly once
                │                                │
                └── every access must stay within bounds

free Ends the Allocation's Lifetime

free(a);
a = NULL;

Setting a to NULL can help prevent accidental reuse through that one variable. It does not change other aliases that pointed to the same allocation:

int *a = malloc(sizeof *a);
int *b = a;
free(a);
a = NULL;
/* b is now dangling */

Cleanup-on-Failure Pattern

Functions that acquire several resources need a plan for partial failure. One common C technique is to centralize cleanup so every acquired resource is released exactly once.

int process(void)
{
    int result = 0;
    int *a = malloc(100 * sizeof *a);
    int *b = NULL;

    if (a == NULL) {
        return -1;
    }

    b = malloc(200 * sizeof *b);
    if (b == NULL) {
        result = -1;
        goto cleanup;
    }

    /* use a and b */

cleanup:
    free(b);  /* free(NULL) is allowed */
    free(a);
    return result;
}
✅ Safety checklist

Check the requested size, check the returned pointer, stay inside the allocated bounds, define ownership, preserve the old allocation if realloc fails, and free each successful allocation exactly once.

#include <stdlib.h>

struct Student
{
    int roll;
    char name[30];
    float marks;
};

int main()
{
    int n, target;

    scanf("%d", &n);

    struct Student *students = malloc((size_t)n * sizeof *students);

    if (students == NULL)
        return 1;

    for (int i = 0; i < n; i++)
        scanf("%d %29s %f", &students[i].roll, students[i].name, &students[i].marks);

    for (int i = 0; i < n; i++)
        printf("%d %s %.1f\n", students[i].roll, students[i].name, students[i].marks);

    scanf("%d", &target);

    for (int i = 0; i < n; i++)
    {
        if (students[i].roll == target)
        {
            printf("Found: %s %.1f", students[i].name, students[i].marks);
            free(students);
            return 0;
        }
    }

    printf("Not Found");

    free(students);

    return 0;
}










17.22 Key Takeaway




        🎯 Remember:

        


malloc() → Allocate memory



calloc() → Allocate + zero-initialize bytes



realloc() → Resize allocation



free() → Release memory



NULL → Check allocation failure



Heap → Common area for dynamic storage



Memory Leak → Allocated memory not released



Dangling Pointer → Pointer to expired/freed object



Use-After-Free → Accessing freed memory







INTERVIEW PREPARATION

🎤 Dynamic Memory Allocation — Interview Questions







1.
What is the difference between malloc() and calloc()?





                malloc() allocates a requested byte count without initializing the block. calloc() allocates an array and initializes the allocated bytes to zero.
            







2.
Why should allocation results be checked against NULL?





                NULL indicates allocation failure, so dereferencing the result would be invalid.
            







3.
Why is using a temporary pointer with realloc() safer?





                If realloc() fails, it returns NULL while the original allocation remains valid. A temporary pointer prevents losing the original address.
            







4.
What is a memory leak?





                It is dynamically allocated storage that remains allocated after the program loses every usable pointer needed to release it.
            







5.
What is a dangling pointer?





                It is a pointer that still contains an address to storage whose lifetime has ended, for example after free().
            







6.
What is a double free?





                It is attempting to free the same allocation more than once without an intervening new allocation. That causes undefined behavior.
            







7.
Does free() set the pointer variable to NULL automatically?





                No. free() releases the allocation, but the pointer variable still contains its old address value until the program changes it.
            







8.
Why is sizeof *ptr often preferred in allocation expressions?





                It automatically matches the type pointed to by ptr and reduces the chance of a type-size mismatch when declarations change.
            









PLACEMENT TIPS

💡 Dynamic Memory Allocation — Placement Tips


    

  • After every important allocation, check whether the returned pointer is NULL before dereferencing it.
    • 

  • Prefer allocation expressions such as malloc(n * sizeof *arr) so the size stays tied to the pointed-to type.
    • 

  • With realloc(), use a temporary pointer and update the original pointer only after success.
    • 

  • Match every successful dynamic allocation with a clear ownership plan for exactly one eventual free().
    • 

  • After free(), do not read or write through that pointer. Setting an owning pointer to NULL can reduce accidental reuse.
    • 

  • In matrix and multi-allocation problems, if a later allocation fails, free every earlier successful allocation before returning.
    •
