🧮 7. Expressions

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

7.1 Expression, Statement and Value — Do Not Mix Them Up

An expression is a combination of operands and operators that computes a value and may also produce side effects. An expression statement is an expression followed by a semicolon. Not every statement is an expression statement; if, for and return have their own statement forms.

a + b        /* expression */
sum = a + b; /* expression statement */
return sum;   /* return statement containing an expression */

7.2 Every Expression Has a Type

The type of the destination variable does not automatically control how an expression is evaluated. Operators first apply C’s conversion rules to operands, the expression produces a value of some type, and only then can assignment convert that result to the destination type.

double x = 5 / 2;   /* 5/2 is int -> 2; assignment converts 2 to 2.0 */
double y = 5 / 2.0; /* 2.0 is double -> floating division -> 2.5 */

7.4 Integer Promotions — Small Integer Types Usually Compute as int

Before many arithmetic/bitwise operations, integer types narrower than int are promoted to int if int can represent all their values; otherwise they may promote to unsigned int.

unsigned char a = 200, b = 20;
int sum = a + b;  /* operands are promoted before addition */
Why students should care

The type of an intermediate expression can be wider or signed differently from the variables that supplied the values. This explains many surprising results in bitwise complement, arithmetic and comparisons.

7.5 Usual Arithmetic Conversions — Finding a Common Type

When binary arithmetic uses operands of different arithmetic types, C applies a hierarchy of conversions to obtain a common type. Floating types generally dominate integer types; among integers, rank and signedness rules determine the common type.

int i = 10;
double d = 2.5;
double r = i + d; /* i converts to double before addition */

Do not memorize a simplistic “smaller converts to larger” rule; signed/unsigned integer combinations can produce results that do not match that phrase.

7.6 Signed and Unsigned Mixing

int s = -1;
unsigned int u = 1;

if (s < u)
    puts("s is smaller");
else
    puts("conversion rules changed the comparison");

Depending on the types/ranks involved, the signed value can be converted to an unsigned type before comparison. A negative value then corresponds to a large unsigned value modulo the unsigned range. Avoid unnecessary signed/unsigned mixing, especially in comparisons.

7.7 Explicit Cast — Ask for a Conversion Deliberately

double average = (double)sum / count;

The cast converts sum to double before division, causing floating-point division. A cast should express an intentional conversion; it should not be used to silence a warning without understanding why the warning exists.

7.8 Precedence Determines Grouping; Associativity Breaks Ties

int x = 2 + 3 * 4;   /* groups as 2 + (3 * 4) -> 14 */
int y = (2 + 3) * 4; /* -> 20 */

Precedence answers which operators bind more tightly. Associativity tells how operators of the same precedence group. Neither concept by itself specifies a universal left-to-right order in which every operand is evaluated.

7.9 Evaluation Order and Sequencing Are Separate from Precedence

The grouping of f() + g() is obvious, but the language does not generally require f() to run before g(). Certain operators, including &&, ||, the first operand of ?:, and the comma operator, impose useful sequencing relationships.

Dangerous pattern

Do not write expressions that both modify and independently access the same scalar object without the required sequencing. Examples often used as “puzzles” can have undefined behavior rather than one clever answer.

7.10 Overflow and Range

Unsigned integer arithmetic is defined modulo one more than the maximum representable value. Signed integer overflow is undefined behavior. Floating overflow/underflow follows the implementation’s floating-point model and library/environment rules.

unsigned int u = UINT_MAX;
u = u + 1u; /* wraps modulo UINT_MAX+1 -> 0 */
Important

Do not teach signed overflow as predictable wraparound even if a particular machine appears to do that in one build.

7.11 Undefined, Implementation-Defined and Unspecified Behavior

TermMeaning
Undefined behaviorThe C standard imposes no requirements on what happens for that program execution.
Implementation-defined behaviorImplementation chooses among permitted possibilities and must document the choice.
Unspecified behaviorStandard permits multiple possibilities and implementation need not document which occurs each time.

These categories are central to writing portable C and should be introduced before students encounter pointer arithmetic, shifts, overflow and sequence-point questions.

7.12 Step-by-Step Expression Analysis Method

1. Identify operand types → 2. Apply grouping → 3. Apply required conversions → 4. Respect sequencing rules → 5. Perform operation → 6. Convert for destination/context
double result = 7 + 5 / 2 * 1.5;

A correct analysis notices that 5 / 2 is integer division first. Its result then participates in multiplication with 1.5, causing floating conversion at that later operation.

7.13 Expression Debugging Checklist

  • What is the type of each operand?
  • Is integer division happening before a later floating conversion?
  • Is there signed/unsigned mixing?
  • Are parentheses clarifying the intended grouping?
  • Does any operand have a side effect?
  • Is that side effect properly sequenced relative to other accesses?
  • Can arithmetic exceed the representable range?
  • Is the final result converted again during assignment or return?

7.14 Quick Revision

📌 Expression → Combination of operands and operators that produces a value.

📌 Parentheses can explicitly control grouping.

📌 * / % generally have higher precedence than + -.

📌 Operators with equal precedence follow their specified associativity.

📌 Integer ÷ Integer → Integer division.

📌 Cast one operand when floating-point division is required.

📌 Zero → false.
📌 Nonzero → true.

7.15 Quick MCQs

1. What is the result of 10 + 5 * 2?
Correct Answer: B

Multiplication has higher precedence than addition. First 5 * 2 = 10, then 10 + 10 = 20.

2. What is the result of 5 / 2 when both operands are int?
Correct Answer: C

With two int operands, integer division is performed. The fractional part is discarded, so the result is 2.

3. Which operator has higher precedence?
Correct Answer: B

* has higher precedence than +, assignment, and logical OR.

4. What is the result of (10 + 5) * 2?
Correct Answer: C

Parentheses force 10 + 5 to be grouped first. 15 * 2 gives 30.

5. What is the value of b after int a = 5; int b = a++; ?
Correct Answer: B

Post-increment yields the old value first, so b receives 5. The side effect then increments a to 6.

6. What is the result of (double)5 / 2?
Correct Answer: C

The cast converts 5 to double before division. Floating-point division is performed, so the mathematical value is 2.5.

7.17 Key Takeaway

🎯 Before evaluating any C expression:

Step 1: Check parentheses.

Step 2: Identify operator precedence.

Step 3: Apply associativity where necessary.

Step 4: Check data types.

Step 5: Check whether integer or floating-point arithmetic is being performed.

Step 6: Evaluate the expression step by step.

This method is extremely useful for C programming exams and coding interviews.

        INTERVIEW PREPARATION
    

🎤 Expressions — Interview Questions








                    1.
                

                    What is an expression in C?
                





                An expression is a combination of operands, operators, constants, variables, and possibly function calls that produces a value.
            








                    2.
                

                    What is the difference between precedence and associativity?
                





                Precedence determines how operators of different precedence levels are grouped. Associativity resolves grouping among operators at the same precedence level.
            








                    3.
                

                    Does operator precedence determine the evaluation order of independent operands?
                





                No. Precedence determines grouping, not the general evaluation order of independent operands.
            








                    4.
                

                    Why does 5 / 2 produce 2 in an integer expression?
                





                Because both operands are integers, integer division is performed and the fractional part is discarded.
            








                    5.
                

                    What is the purpose of explicit type casting in an expression?
                





                A cast requests conversion of a value to another type, which can change how the surrounding expression is evaluated.
            








                    6.
                

                    What is the result of a relational or logical expression in C?
                





                Such expressions produce an int value: 0 for false and 1 for true when produced by relational or logical operators.
            








                    7.
                

                    Why should expressions such as i++ + ++i be avoided?
                





                They can modify the same scalar object multiple times without the sequencing required by C, which can lead to undefined behavior.
            








                    8.
                

                    How can parentheses improve expressions?
                





                Parentheses make the intended grouping explicit, improve readability, and can override the normal precedence-based grouping.
