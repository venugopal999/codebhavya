🔢 19. Bitwise Programming

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

19.1 Bitwise Programming Starts with Binary Representation

Bitwise programming treats integer values as groups of binary bits. A bit is either 0 or 1. Operators can test, set, clear, toggle or shift selected positions without changing unrelated bits.

decimal 13
binary   1101
bit pos  3210

19.2 Use Unsigned Types When the Goal Is a Bit Pattern

Unsigned integer operations have defined modulo arithmetic and clearer shift behavior for low-level masks. Signed negative values introduce representation and right-shift concerns that distract from the intended bit pattern.

uint32_t flags = 0; /* when uint32_t is provided */
unsigned int mask = 1u << 3;

19.3 Bitwise AND &

ABA & B
000
010
100
111

AND keeps a 1 only where both operands have 1. Therefore it is ideal for testing selected bits or clearing positions using an appropriate mask.

19.4 Bitwise OR |

ABA | B
000
011
101
111

OR produces 1 where either operand has 1. OR with a mask is the standard pattern for setting selected flag bits.

19.5 Bitwise XOR ^

ABA ^ B
000
011
101
110

XOR produces 1 where bits differ. XOR with a mask toggles selected bits, which makes it useful for reversible flag changes and parity-like algorithms.

19.6 Bitwise Complement ~

x  = 00000101
~x = 11111010

~ flips every bit after integer promotion. The width of the promoted type matters; drawing only 8 bits is a visualization, not necessarily the width of the actual computation.

19.7 Left Shift <<

unsigned x = 5u;   /* ...0101 */
unsigned y = x << 1; /* ...1010 */

For a valid shift count, unsigned left shift moves bits left and introduces zeros at the low end, with the result defined modulo the unsigned width. Bits shifted out are lost.

19.8 Right Shift >>

unsigned x = 20u;  /* 10100 */
unsigned y = x >> 2; /* 00101 -> 5 */

Unsigned right shift shifts in zeros at the high end. This is the clearest form for extracting bit fields.

19.9 Validate Shift Counts

A shift count must be nonnegative and less than the width of the promoted left operand. Shifting by the type width or more is undefined behavior.

unsigned width = sizeof(value) * CHAR_BIT;
if (k < width)
    result = value << k;

19.10 Test a Bit

(value & (1u << bit)) != 0
if ((flags & (1u << bit)) != 0)
    puts("bit is set");

The mask contains 1 only at the position of interest. AND clears every other result bit, so a nonzero result means the selected bit was 1.

19.11 Set a Bit

value |= (1u << bit)

OR forces the selected bit to 1 because x | 1 is always 1 while positions where the mask has 0 retain their original bit.

19.12 Clear a Bit

value &= ~(1u << bit)

First build a one-bit mask, complement it so every position is 1 except the target bit, then AND with the value.

19.13 Toggle a Bit

value ^= (1u << bit)

XOR with 1 flips a bit; XOR with 0 preserves it.

19.14 Extract a Multi-Bit Field

(value >> shift) & mask
unsigned field = (value >> 4) & 0x7u; /* extract 3 bits */

Shift the desired field down to bit 0, then mask away unrelated higher bits.

19.15 Replace a Multi-Bit Field

unsigned fieldMask = 0x7u << 4;
value = (value & ~fieldMask) | ((newField & 0x7u) << 4);

Clear the old field first, constrain the new value to the field width, shift it into position, then combine with OR.

19.16 Count Set Bits

unsigned count = 0;
while (x != 0)
{
    x &= x - 1; /* clears lowest set bit */
    count++;
}

x & (x-1) removes the least-significant 1 bit. Therefore the loop executes once per set bit rather than once per bit position.

19.17 Check Power of Two

int isPowerOfTwo = x != 0 && (x & (x - 1)) == 0;

A positive power of two has exactly one set bit. Subtracting 1 turns that bit off and all lower bits on; ANDing the two values gives zero.

19.18 Shift Is Not Rotation

A shift discards bits that leave the width. A rotation deliberately reintroduces those bits at the opposite end. C provides shift operators, not a universal built-in rotate operator in classic language versions; rotation requires a width-aware expression or implementation intrinsic.

19.19 Bit Masks vs Structure Bit-Fields

Masks on unsigned integersStructure bit-fields
Explicit shifts/masks; good for protocols/register valuesConvenient named fields in a structure
Bit positions controlled by your expressionsPhysical allocation order has implementation-defined aspects
Often preferred for defined external layoutsGood for implementation-controlled compact state

19.20 Quick Revision

📌 & → AND

📌 | → OR

📌 ^ → XOR

📌 ~ → NOT

📌 << → Left shift

📌 >> → Right shift

📌 n & 1 → Check least significant bit

📌 n | (1u << k) → Set bit

📌 n & ~(1u << k) → Clear bit

📌 n ^ (1u << k) → Toggle bit

📌 n & (n - 1) → Remove lowest set bit

📌 n & (n - 1) == 0 → Power-of-two test when n is positive

Correct Answer: B

The ^ operator performs bitwise exclusive OR.











3.
Which operator flips bits?
















Correct Answer: D

The unary ~ operator produces the bitwise complement.











4.
What is 5 & 3?
















Correct Answer: A

5 is 0101 and 3 is 0011. Their bitwise AND is 0001, which is 1.











5.
What is 5 | 3?
















Correct Answer: C

0101 | 0011 gives 0111, which is 7.











6.
What is 5 ^ 3?
















Correct Answer: B

0101 ^ 0011 gives 0110, which is 6.











7.
Which operator performs left shift?
















Correct Answer: A

The << operator shifts bits toward more-significant positions.











8.
Which expression checks whether bit k is set?
















Correct Answer: A

A mask with only bit k set is ANDed with n. A non-zero result means bit k is set.











9.
Which expression sets bit k?
















Correct Answer: B

OR with a one-bit mask forces bit k to 1 while preserving other bits.











10.
Which expression removes the lowest set bit?
















Correct Answer: C

For non-zero n, n & (n - 1) clears the lowest set bit.

        🎯 Remember:

        


AND (&) → Select bits



OR (|) → Set bits



XOR (^) → Toggle / find differences



NOT (~) → Flip bits

INTERVIEW PREPARATION

🎤 Bitwise Programming — Interview Questions







1.
What is the difference between bitwise & and logical &&?





                Bitwise & operates on corresponding bits of integer operands. Logical && evaluates truth values and uses short-circuit evaluation.
            







2.
Why are unsigned integers often preferred for bit manipulation?





                Unsigned operations have well-defined modulo arithmetic and right-shift behavior, making bit-level intent clearer and avoiding several signed-integer pitfalls.
            







3.
How do you check whether bit k is set?





                Create a one-bit mask such as 1u << k and test whether n & mask is non-zero.
            







4.
How do you clear bit k without changing other bits?





                Use n &= ~(1u << k). The complemented mask has a zero only at bit k.
            







5.
Why does n & (n - 1) remove the lowest set bit?





                Subtracting one changes the lowest set 1 to 0 and turns the lower zero bits into ones; AND therefore removes exactly that lowest set bit.
            







6.
How can XOR find one unique element when all others appear twice?





                XOR is associative and commutative, and x ^ x is 0. Equal pairs cancel, leaving the unique value.
            







7.
How do bit flags represent multiple permissions?





                Each permission uses a different bit. OR combines permissions, AND tests them, AND with a complemented mask clears them, and XOR toggles them.
            







8.
What shift mistake should be avoided?





                Do not shift by a negative count or by a count greater than or equal to the width of the promoted left operand; that is undefined behavior.
            









PLACEMENT TIPS

💡 Bitwise Programming — Placement Tips


    

  • For bit-position problems, write the mask first: 1u << k. Then decide whether the task needs &, |, ^, or ~.
    • 

  • Prefer unsigned values when a problem is specifically about binary representation and bit manipulation.
    • 

  • Remember the three core mask formulas: set with |, clear with & ~mask, and toggle with ^.
    • 

  • For power-of-two questions, handle zero separately before using n & (n - 1).
    • 

  • XOR is especially useful when duplicate values occur in pairs because equal values cancel.
    • 

  • Be careful with operator precedence; add parentheses around bitwise expressions when combining them with comparisons or arithmetic.
