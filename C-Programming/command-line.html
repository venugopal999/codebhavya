💻 18. Command Line Arguments

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

18.1 What Command-Line Arguments Are

A program can receive strings from its execution environment when it starts. In the common hosted form, argc reports how many argument strings are available and argv points to an array of pointers to those strings.

int main(int argc, char *argv[])
{
    /* ... */
}

18.2 char *argv[] and char **argv in a Parameter List

In a function parameter declaration, char *argv[] is adjusted to char **argv. They describe the same parameter type in the common main declaration context.

int main(int argc, char **argv)

18.3 The Shape of argv

argv
  │
  ├─ argv[0] → program name/path string (when supplied by environment)
  ├─ argv[1] → first user argument
  ├─ argv[2] → second user argument
  └─ argv[argc] = NULL

For positive argc in the standard hosted model, argv[0] conventionally represents the program invocation name when available. The array terminates with a null pointer at argv[argc].

18.4 Arguments Are Strings, Even When They Look Numeric

/* command: app 25 3.5 */
/* argv[1] points to "25"; argv[2] points to "3.5" */

Arithmetic requires conversion from text to a numeric type. The text itself is not automatically an int or double.

18.5 Why atoi Is Convenient but Weak for Validation

int n = atoi(argv[1]);

atoi cannot cleanly distinguish several invalid-input cases from a legitimate converted zero and provides limited error information. For robust input validation, strtol or related functions are preferable.

18.6 Validated Integer Conversion with strtol

errno = 0;
char *end;
long value = strtol(argv[1], &end, 10);

if (errno == ERANGE || end == argv[1] || *end != '\0')
{
    fprintf(stderr, "Invalid integer\n");
    return EXIT_FAILURE;
}

A robust conversion checks: whether any digits were consumed, whether trailing unwanted characters remain, and whether the result was outside the representable range of long.

18.7 Range-Check Before Narrowing to int

if (value < INT_MIN || value > INT_MAX)
{
    fprintf(stderr, "Out of int range\n");
    return EXIT_FAILURE;
}
int n = (int)value;

Successful conversion to long does not prove the value fits a narrower destination type. Validate the destination range before casting.

18.8 Base Argument in strtol

strtol(text, &end, 10); /* decimal only */
strtol(text, &end, 0);  /* recognizes supported prefixes such as 0x */

Use base 10 when decimal input is required. Base 0 intentionally lets the textual prefix participate in choosing the base; that can be useful or surprising depending on the interface.

18.9 Quoted Arguments and the Shell

The C program usually does not parse the user’s raw command line itself. A shell or runtime often handles quoting, escaping, wildcard expansion or environment-specific transformations before main receives argv.

app "Computer Science" 2026

The intent is that "Computer Science" reaches the program as one argument string when processed by a shell with that quoting convention. Exact shell rules are outside the C language specification.

18.10 Check argc Before Accessing argv Elements

if (argc != 3)
{
    fprintf(stderr, "Usage: %s <a> <b>\n", argv[0]);
    return EXIT_FAILURE;
}

Accessing argv[2] when fewer arguments were supplied is invalid. Argument-count checks should happen before conversion or use.

18.11 Options vs Positional Arguments

A command-line interface often distinguishes options such as -v or --output=file from positional values such as input filenames. Even a simple parser should define order, repetition, missing-value behavior and unknown-option behavior clearly.

18.12 File Names as Arguments

if (argc < 2) return EXIT_FAILURE;
FILE *fp = fopen(argv[1], "r");
if (fp == NULL)
{
    perror(argv[1]);
    return EXIT_FAILURE;
}

Command-line arguments frequently provide file paths, but path syntax, encoding and permissions are environment-specific. Always check file-opening results.

18.13 Portable Exit Status

#include <stdlib.h>
return EXIT_SUCCESS;
/* or */
return EXIT_FAILURE;

EXIT_SUCCESS and EXIT_FAILURE express portable success/failure intent. Returning 0 from main also denotes success in hosted C.

18.14 Command-Line Processing Workflow

Check argc → parse each string → validate syntax → validate numeric/range meaning → open resources → perform work → report errors clearly

Treat command-line input as untrusted text. Parsing and validation should be explicit, just like interactive input validation.

What are Command Line Arguments?

Command line arguments are values supplied to a C program when the program is started from a command line or terminal.

They allow a program to receive input without using scanf() during execution.

Command Line
↓
Program + Arguments
↓
main(argc, argv)
↓
Program Processing

Example: 

program.exe 10 20 30

Here 10, 20 and 30 are command line arguments.

main() with Command Line Arguments

A common form of the main function is: 

int main(int argc, char *argv[])
{
    return 0;
}

The two parameters are:

  • argc → argument count
  • argv → argument vector, an array of pointers to the argument strings

argc - Argument Count

argc contains the number of command-line arguments, including the program name.

Example: 

program.exe 10 20

The value of argc is:

argc = 3

Why 3?

Program name → 1
10 → 1
20 → 1

Total = 3

argv - Argument Vector

argv is an array of strings containing the command-line arguments. 

program.exe 10 20
argv[0] program.exe
argv[1] 10
argv[2] 20

Display Command Line Arguments

#include <stdio.h>

int main(int argc, char *argv[])
{
    printf("Argument count = %d\n\n", argc);

    for(int i = 0; i < argc; i++)
    {
        printf("argv[%d] = %s\n", i, argv[i]);
    }

    return 0;
}

Suppose the program is executed as: 

program.exe Hello 123 C
Argument count = 4

argv[0] = program.exe
argv[1] = Hello
argv[2] = 123
argv[3] = C

Important: Command Line Arguments are Strings

All command-line arguments are received as strings. 

program.exe 10 20

Therefore: 

argv[1]

contains the string: 

"10"

It is not automatically an integer.

📌 If you need numeric calculations, convert the argument string to a number first.

Converting Strings to Integers - atoi()

The atoi() function converts a string representing an integer into an int. 

#include <stdlib.h>

int num;

num = atoi(argv[1]);

Example: 

program.exe 25
int num = atoi(argv[1]);

Now:

num = 25

Find the Largest Command Line Number

#include <stdio.h>
#include <stdlib.h>

int main(int argc, char *argv[])
{

    {
        printf("Provide at least one number");

strtol() - Safer Integer Conversion

atoi() is simple, but it provides limited error reporting. For more robust programs, strtol() can be used. 

#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <limits.h>

int main(int argc, char *argv[])
{
    if(argc != 2)
    {
        printf("Usage: program number");
        return 1;
    }

    char *end;
    long value;

    errno = 0;

    value = strtol(argv[1], &end, 10);

    if(end == argv[1] || *end != '\0')
    {
        printf("Invalid integer");
        return 1;
    }

    if(errno == ERANGE ||
       value < INT_MIN ||
       value > INT_MAX)
    {
        printf("Integer out of range");
        return 1;
    }

    printf("Number = %ld", value);

    return 0;
}

Passing a Character or Word

#include <stdio.h>

int main(int argc, char *argv[])
{
    if(argc != 2)
    {
        printf("Usage: program name");
        return 1;
    }

    printf("Hello %s!", argv[1]);

    return 0;
}

Example: 

program.exe Venu
Hello Venu!

If an argument contains spaces, the shell normally separates it into multiple arguments unless it is quoted. 

program.exe "Venu Gopal"

Checking the Number of Arguments

A program should check whether the required arguments have been provided before accessing them. 

if(argc != 3)
{
    printf("Usage: program number1 number2");
    return 1;
}
⚠️ Never access argv[1], argv[2], etc. unless the corresponding argument is known to exist.

Command Line Calculator

#include <stdio.h>
#include <stdlib.h>

int main(int argc, char *argv[])
{
    if(argc != 4)
    {
        printf("Usage: program number operator number");
        return 1;
    }

    int a = atoi(argv[1]);
    int b = atoi(argv[3]);

    char op = argv[2][0];

    switch(op)
    {
        case '+':
            printf("Result = %d", a + b);
            break;

        case '-':
            printf("Result = %d", a - b);
            break;

        case '*':
            printf("Result = %d", a * b);
            break;

        case '/':
            if(b == 0)
            {
                printf("Division by zero is not allowed");
                return 1;
            }

            printf("Result = %d", a / b);
            break;

        default:
            printf("Invalid operator");
    }

    return 0;
}

Example: 

program.exe 10 + 20
Result = 30

Passing a File Name

Command-line arguments are often useful for supplying file names. 

#include <stdio.h>

int main(int argc, char *argv[])
{
    if(argc != 2)
    {
        printf("Usage: program filename");
        return 1;
    }

    FILE *fp = fopen(argv[1], "r");

    if(fp == NULL)
    {
        printf("Unable to open file");
        return 1;
    }

    printf("File opened successfully");

    fclose(fp);

    return 0;
}

Example: 

program.exe data.txt
🔍 Deeper understanding: Arguments are strings and must be validated

argc is nonnegative, argv[0] normally identifies the program when available, and argv[argc] is a null pointer. Every supplied argument is text, even when it visually contains a number. Shell quoting and wildcard expansion usually happen before the C program receives its argument array.

if (argc != 2) {
    fprintf(stderr, "Usage: %s integer\\n", argv[0]);
    return EXIT_FAILURE;
}

char *end;
errno = 0;
long value = strtol(argv[1], &end, 10);
if (errno != 0 || end == argv[1] || *end != '\0') {
    fprintf(stderr, "Expected a valid integer\\n");
    return EXIT_FAILURE;
}

atoi cannot reliably distinguish invalid input from a valid zero. strtol provides an end pointer and range-error reporting. Check argc before accessing an argument, print usage information to stderr, and return EXIT_SUCCESS or EXIT_FAILURE from <stdlib.h>.

Common Mistakes

  • Forgetting that argv contains strings.
  • Using argv[1] without checking argc.
  • Performing arithmetic directly on strings.
  • Forgetting to convert numeric arguments.
  • Assuming the program name is not counted in argc.
  • Using atoi() when detailed input validation is required.
  • Forgetting that arguments containing spaces may need quoting in the command shell.
Reasoning trace:
argv text → strtol conversion → verify digits consumed → verify end is \0 → verify range → use value
📘 Standard and portability note

Argument quoting and wildcard expansion are normally shell behaviours, not rules implemented by C itself.

🧠 Deep Dive — How argv Arrives, Safe Conversion and Command-Line Interface Design

Two Equivalent Ways to Write the Common main Signature

int main(int argc, char *argv[])
int main(int argc, char **argv)

In a function parameter declaration, the array form adjusts to a pointer form. In both cases, argv lets the program access a sequence of pointers to argument strings.

The Shape of argv

argc = 3

argv[0] ──► "program"
argv[1] ──► "25"
argv[2] ──► "report.txt"
argv[3] ──► NULL

argv[argc] is a null pointer. When a program name is available, argv[0] contains a string representing how the program was invoked. Do not depend on it being a full filesystem path.

The Shell Usually Processes the Command Line First

On many systems, quoting, escaping, environment-variable expansion, wildcard expansion or redirection can be handled by a shell before the program begins. C itself does not define one universal shell syntax.

program "hello world"

A typical shell passes hello world as one argument because of its quoting rules. Another execution environment can use different rules.

Use strtol for Validated Integer Conversion

#include <errno.h>
#include <limits.h>
#include <stdlib.h>

char *end;
errno = 0;
long value = strtol(argv[1], &end, 10);

if (end == argv[1]) {
    /* no digits were converted */
} else if (*end != '\0') {
    /* extra characters remain */
} else if (errno == ERANGE) {
    /* result is outside long range */
} else {
    /* valid long value */
}
💡 Why is atoi weak for validation?

atoi returns an int but gives no robust way to distinguish a valid textual zero from conversion failure, and its behavior on out-of-range input is not a good foundation for validation. strtol exposes where parsing stopped and provides range-error reporting.

Base 0 Lets strtol Recognize Prefixes

long value = strtol(text, &end, 0);

With base 0, the function can select a base from the input's accepted prefix rules. For a user interface that must accept decimal only, explicitly request base 10 instead of silently accepting other forms.

Convert, Then Range-Check for the Destination Type

long temp = strtol(argv[1], &end, 10);
if (temp < INT_MIN || temp > INT_MAX) {
    /* does not fit in int */
} else {
    int value = (int)temp;
}

Successful conversion to long does not automatically prove that the value fits a smaller destination type such as int.

Separate Options from Positional Arguments

A clear command-line interface documents which inputs are options and which are positional data. A common convention is:

program --verbose --output result.txt input.txt

C itself does not standardize one option parser or require the --name convention. The program can implement its own parser or use platform/library facilities appropriate to the project.

Use Standard Exit Status Macros

return EXIT_SUCCESS;
return EXIT_FAILURE;

EXIT_SUCCESS and EXIT_FAILURE come from <stdlib.h> and express intent more portably than inventing arbitrary success/failure numbers.

✅ Robust command-line sequence

Check argc → identify each argument's purpose → convert text with a function that reports errors → validate the entire string → check the destination range → report usage/errors through an appropriate stream → return a meaningful status.

INTERVIEW PREPARATION

🎤 Command Line Arguments — Interview Questions







1.
What do argc and argv represent?





                argc is the number of command-line argument strings passed to main(), while argv is the array of pointers to those strings.
            







2.
Why should argc be checked before argv[i] is used?





                Because accessing an argument index that was not supplied reads beyond the valid argument entries.
            







3.
Why are numeric command-line arguments still strings?





                The program receives command-line arguments as character sequences. Numeric text must be converted before numeric operations.
            







4.
Why is strtol() usually better than atoi() for validated input?





                strtol() provides an end pointer and error signaling that can be used to detect incomplete or out-of-range conversions.
            







5.
How can a single argument contain spaces?





                The invoking shell or command environment usually requires quoting the text so that it is passed as one argument.
            







6.
What is typically stored in argv[0]?





                By convention it usually represents the program invocation name, although the exact string is environment-dependent.
            







7.
How many user arguments are present when argc is 5?





                Normally four user arguments, because argv[0] occupies one entry.
            







8.
What is a common command-line programming mistake?





                Assuming required arguments exist without validating argc, or converting numeric text without checking whether conversion succeeded.
            









PLACEMENT TIPS

💡 Command Line Arguments — Placement Tips


    

  • Before accessing argv[n], verify that argc > n.
    • 

  • Remember that every command-line argument arrives as a string, even when it looks like a number.
    • 

  • Prefer strtol() or related conversion functions when invalid input must be detected reliably.
    • 

  • When a value contains spaces, it generally needs quoting in the command line so that it reaches the program as one argument.
    • 

  • argv[0] is normally the program invocation name; user arguments usually begin at argv[1].
    • 

  • For calculator and utility programs, validate both the argument count and the content before performing the requested operation.
