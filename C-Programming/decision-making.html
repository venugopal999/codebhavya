🔀 8. Decision Making

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

8.1 Decision Making Means Choosing a Control-Flow Path

Decision statements evaluate a condition and choose which statement or block executes next. The key idea is not merely syntax such as if; it is control flow: the program may follow different paths for different data.

condition
   ├── true  → path A
   └── false → path B

8.2 Truth and Falsehood in C

In a controlling expression, zero is false and any nonzero scalar value is true. Relational and logical operators produce 0 or 1, but if can test other scalar expressions too.

int x = -5;
if (x)
    puts("nonzero -> true");
Do not confuse truth with the value 1

A condition does not have to equal exactly 1 to be true. Any nonzero value is treated as true.

8.3 Simple if Statement

if (temperature > 40)
{
    puts("High temperature");
}

The condition is evaluated first. If it is nonzero, the controlled statement/block executes. If it is zero, control continues after the if statement.

8.4 if-else: Exactly One of Two Alternatives

if (n % 2 == 0)
{
    puts("Even");
}
else
{
    puts("Odd");
}

For one execution of this statement, exactly one branch is selected. The second branch is not separately tested; it is the fallback when the first condition is false.

8.5 else-if Ladder — First Matching Branch Wins

if (marks >= 90)
    grade = 'A';
else if (marks >= 75)
    grade = 'B';
else if (marks >= 60)
    grade = 'C';
else
    grade = 'D';

Conditions are evaluated from top to bottom until one is true. Therefore condition order is part of the algorithm. If a broad condition appears before a narrower one, the narrower branch may never be reached.

8.6 Nested if — A Decision Inside Another Decision

if (usernameValid)
{
    if (passwordValid)
        puts("Login allowed");
    else
        puts("Wrong password");
}

Nesting is useful when the second decision is meaningful only after the first succeeds. Deep nesting can reduce readability; combine conditions or extract functions when that communicates the rule more clearly.

8.7 Dangling else — Which if Receives the else?

if (a > 0)
    if (b > 0)
        puts("both positive");
    else
        puts("b is not positive");

Without braces, an else associates with the nearest unmatched if. This is legal C but easy to misread. Braces make intended structure explicit.

if (a > 0)
{
    if (b > 0)
        puts("both positive");
}
else
{
    puts("a is not positive");
}

8.8 switch Statement — Multi-Way Selection on Discrete Values

switch (choice)
{
    case 1:
        puts("Add");
        break;
    case 2:
        puts("Delete");
        break;
    default:
        puts("Invalid choice");
}

The controlling expression has an integer or enumeration type after permitted promotions. Each case label uses an integer constant expression. switch is not a general replacement for ranges such as score >= 90.

8.9 break and Fall-Through in switch

break exits the nearest enclosing switch or loop. Without it, execution continues into following case statements after a matching label is entered. This is called fall-through.

switch (grade)
{
    case 'A':
    case 'B':
        puts("Pass with strong grade");
        break;
    default:
        puts("Other grade");
}
Intentional vs accidental

Grouped labels can intentionally use fall-through. When fall-through is not intended, a missing break is a common bug.

8.10 if-else vs switch — Choose by the Shape of the Condition

Use if/else whenUse switch when
Ranges or inequalities are centralComparing one expression against discrete constant values
Different variables participate in conditionsMenu/state values map naturally to cases
Complex logical expressions are neededCases improve readability of many exact-value alternatives

8.11 Conditional Operator ?: for Choosing a Value

int max = (a > b) ? a : b;

The conditional operator is an expression: it chooses one of two expression results. Use it for compact value selection, not to compress large blocks of unrelated statements.

8.12 goto and Labels — Unconditional Transfer

if (resource2_failed)
    goto cleanup_resource1;

/* normal work */

cleanup_resource1:
    release_resource1();

goto transfers control to a label within the same function. Most ordinary decisions/loops are clearer with structured constructs, but carefully used forward jumps can simplify centralized cleanup in low-level C code.

8.13 Boundary Conditions Are Part of the Requirement

A condition can look correct while being wrong at the boundary. Translate words such as “at least,” “more than,” “between,” and “up to” into operators carefully.

RequirementTypical condition
At least 18age >= 18
More than 18age > 18
From 10 through 100n >= 10 && n <= 100
Outside 10..100n < 10 || n > 100

8.14 Decision-Design Method

State the rule in words → identify mutually exclusive cases → write boundary values → choose if/switch → test every boundary and fallback

Testing only “normal” middle values hides many decision bugs. For a pass mark of 40, test 39, 40 and 41—not only 75.

8.15 Quick Revision

📌 if → One condition

📌 if-else → Two alternatives

📌 else-if → Multiple conditions

📌 Nested if → Decision inside another decision

📌 switch → Multiple discrete choices

📌 break → Exit switch

📌 default → No case matched

📌 Always test boundary cases.

        case '*': printf("%d", a * b); break;
        case '/':
            if (b != 0) printf("%d", a / b);

            break;
        default: printf("Invalid operator");
    }

    return 0;
}

INTERVIEW PREPARATION
🎤 Decision Making — Interview Questions
1.What is the difference between if and if-else?
if executes a block only when its condition is true. if-else selects between a true branch and a false branch.
2.Why does the order of conditions matter in an else-if ladder?
Conditions are checked from top to bottom, and the first true branch is executed. Later conditions are skipped.
3.When is switch preferred over if-else?
switch is convenient for selecting among discrete constant case values such as menu choices, while if-else is better for ranges and complex logical conditions.
4.What happens when break is omitted in a switch case?
Execution can continue into following case labels until a break or the end of the switch is reached. This is called fall-through.
5.What is the role of default in switch?
default handles the situation in which none of the case values match the switch expression.
6.What is a nested if statement?
A nested if is an if statement inside another if or else block, used when a second decision depends on the first.
7.Why are boundary cases important in decision-making programs?
They verify behavior exactly at and around condition limits, such as marks 39, 40, and 41 for a pass mark of 40.
8.What common mistake occurs with = and == inside conditions?
= performs assignment, while == performs equality comparison. Accidentally using = can change a value and produce unintended condition results.


PLACEMENT TIPS
💡 Decision Making — Placement Tips
  • For an else-if ladder, write the most restrictive or highest-range conditions first when ranges overlap.
  • Always test the exact boundary values around a condition: for a pass mark of 40, test 39, 40 and 41.
  • Use switch for discrete menu values; use if-else for ranges, relational tests and compound logical conditions.
  • In output-prediction questions, trace only the branch that actually executes and remember that an else-if ladder stops at the first true condition.
  • When using switch, check whether fall-through is intentional before omitting break.
  • Keep nested decisions readable. If nesting becomes deep, simplify the conditions or split the logic into smaller functions later.
