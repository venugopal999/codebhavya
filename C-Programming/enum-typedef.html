🔤 20. Enumerations (enum) and typedef

🎓 Concept-First Explanation

This lesson is organized in the same order a faculty member would normally teach it: meaning → purpose → syntax/model → internal working → examples → common confusion → safe use. The guided examples from the earlier lesson are preserved afterward for reinforcement.

20.1 enum Gives Names to Integral Constants

enum Day
{
    MONDAY,
    TUESDAY,
    WEDNESDAY
};

The enumerators are named integer constants. When no explicit value is given, the first starts at 0 and each following enumerator is one greater than the previous value.

20.2 Explicit and Mixed Enumerator Values

enum Status
{
    STATUS_OK = 0,
    STATUS_RETRY = 10,
    STATUS_TIMEOUT,   /* 11 */
    STATUS_FATAL = 100
};

Enumerator values do not have to be consecutive. After an explicitly assigned value, a following implicit enumerator continues from that value plus one.

20.3 enum Variables Represent a Domain of Named States

enum TrafficLight light = GREEN;
switch (light)
{
    case RED:    /* ... */ break;
    case YELLOW: /* ... */ break;
    case GREEN:  /* ... */ break;
}

Using names such as GREEN communicates domain meaning better than scattering unexplained numbers through control flow.

20.4 State Values Are Different from Bit Flags

An enum for mutually exclusive states might use 0,1,2. Independent flags need distinct bits such as 1,2,4,8 so they can be combined.

enum Permission
{
    PERM_READ  = 1u << 0,
    PERM_WRITE = 1u << 1,
    PERM_EXEC  = 1u << 2
};

This “enum as named mask constants” pattern is different from using one enum object to represent exactly one state.

20.5 Do Not Assume a Particular enum Storage Width for External Formats

The implementation chooses a compatible integer type according to the language/version rules. sizeof(enum X) is therefore not a portable protocol specification. Serialize external values explicitly when exact width matters.

20.6 Sentinel Enumerator for Counts

enum Color { RED, GREEN, BLUE, COLOR_COUNT };
const char *names[COLOR_COUNT] = {"Red", "Green", "Blue"};

A final count enumerator is convenient when values are consecutive from zero. Do not use this pattern when explicit sparse values break the counting relationship.

20.7 typedef Creates a Type Alias

typedef unsigned long ulong;
ulong count = 0;

typedef introduces another name for an existing type. It does not create a new runtime object and generally does not create a strongly distinct type identity that prevents mixing with the aliased type.

20.8 typedef with Structures

typedef struct Student
{
    int id;
    double cgpa;
} Student;

Student s;

This pattern lets later declarations write Student instead of struct Student. Keeping the tag is useful for self-reference and debugging/tooling contexts.

20.9 typedef with enum

typedef enum
{
    MODE_OFF, MODE_ON
} Mode;

Mode m = MODE_ON;

20.10 Pointer typedefs Can Hide the Pointer Nature

typedef char *StringPtr;
const StringPtr p = buffer;

Here const qualifies the typedef name as a whole, making the pointer itself const rather than making the pointed-to chars const. Pointer typedefs can make declarations shorter but can also hide important ownership/const details.

typedef char *StringPtr;
/* const StringPtr == char * const, not const char * */

20.11 typedef for Function Pointers

typedef int (*CompareFn)(const void *, const void *);
CompareFn cmp = myCompare;

Function-pointer syntax becomes much easier to read when a well-named typedef describes the callable interface.

20.12 typedef vs #define for Type Names

typedef unsigned long ULong;
#define ULONG unsigned long

typedef participates in C’s type grammar and handles complex declarators correctly. A macro merely substitutes preprocessing tokens. Prefer typedef for type aliases.

20.13 enum + typedef Together

typedef enum
{
    STATE_IDLE,
    STATE_RUNNING,
    STATE_ERROR
} State;

This combines readable named state constants with a convenient type alias for variables, parameters and structure members.

20.15 Guided Examples & Reinforcement

Now revisit the original worked examples, short explanations and visual examples. They are retained here to reinforce the concepts explained above.

What is an enum?

An enum (enumeration) is a user-defined type in C that gives meaningful names to a set of integer constants.

It improves the readability of programs when a variable can have one value from a fixed set of choices. 

enum Day
{
    SUNDAY,
    MONDAY,
    TUESDAY,
    WEDNESDAY,
    THURSDAY,
    FRIDAY,
    SATURDAY
};

By default, the first enumerator has value 0, the next has value 1, and so on.

Declaring an enum Variable

enum Day today;

today = MONDAY;

A variable declared as enum Day can store an enumeration value. 

#include <stdio.h>

enum Day
{
    SUNDAY,
    MONDAY,
    TUESDAY,
    WEDNESDAY,
    THURSDAY,
    FRIDAY,
    SATURDAY
};

int main()
{
    enum Day today = MONDAY;

    printf("%d", today);

    return 0;
}

enum with switch

Enums are especially useful with switch statements. 

#include <stdio.h>

enum Day
{
    SUNDAY,
    MONDAY,
    TUESDAY,
    WEDNESDAY,
    THURSDAY,
    FRIDAY,
    SATURDAY
};

int main()
{
    enum Day day = WEDNESDAY;

    switch(day)
    {
        case SUNDAY:
            printf("Sunday");
            break;

        case MONDAY:
            printf("Monday");
            break;

        case TUESDAY:
            printf("Tuesday");
            break;

        case WEDNESDAY:
            printf("Wednesday");
            break;

        case THURSDAY:
            printf("Thursday");
            break;

        case FRIDAY:
            printf("Friday");
            break;

        case SATURDAY:
            printf("Saturday");
            break;
    }

    return 0;
}

Advantages of enum

  • Makes code easier to read.
  • Provides meaningful names for integer constants.
  • Useful when a variable has a fixed set of logical choices.
  • Works naturally with switch statements.
  • Reduces the use of unexplained numeric constants.

Real-Life Example: Traffic Light

#include <stdio.h>

enum TrafficLight
{
    RED,
    YELLOW,
    GREEN
};

int main()
{
    enum TrafficLight light = GREEN;

    if(light == RED)
    {
        printf("STOP");
    }
    else if(light == YELLOW)
    {
        printf("READY");
    }
    else
    {
        printf("GO");
    }

    return 0;
}

Size of an enum

The size of an enum is implementation-defined. It is commonly the size of an integer type, but portable C code should not assume a specific size. 

#include <stdio.h>

enum Color
{
    RED,
    GREEN,
    BLUE
};

int main()
{
    printf("%zu", sizeof(enum Color));

    return 0;
}

Important Point About enum

📌 The names declared inside an enum are integer constants.

📌 The exact underlying representation of an enum is implementation-defined.

📌 Do not assume every enum object must occupy exactly 4 bytes.

What is typedef?

typedef creates an alternative name (alias) for an existing type.

It does not create a completely new type. 

typedef int Number;

Now both of the following declare an integer: 

int a;

Number b;

Basic typedef Example

#include <stdio.h>

typedef int Number;

int main()
{
    Number x = 100;

    printf("%d", x);

    return 0;
}
100

typedef with Multiple Variables

typedef unsigned int UINT;

UINT a = 10;
UINT b = 20;

This can make declarations shorter and easier to read.

typedef with Structure

Without typedef: 

struct Student
{
    int id;
    char name[50];
};

struct Student s1;

With typedef: 

typedef struct
{
    int id;
    char name[50];
} Student;

Student s1;

This is one of the most common uses of typedef in C.

Complete typedef Structure Example

#include <stdio.h>

typedef struct
{
    int id;
    char name[50];
    float marks;
} Student;

int main()
{
    Student s;

    s.id = 101;
    s.marks = 85.5;

    printf("ID = %d\n", s.id);
    printf("Marks = %.2f\n", s.marks);

    return 0;
}
ID = 101
Marks = 85.50

typedef with enum

typedef can also be used with enum. 

typedef enum
{
    LOW,
    MEDIUM,
    HIGH
} Level;

Now you can simply write: 

Level current = HIGH;

typedef with Pointer

typedef int* IntPtr;

int x = 10;

IntPtr p = &x;

Here IntPtr is an alias for int *.

Important typedef Pointer Example

typedef int* IntPtr;

IntPtr p1, p2;

Both p1 and p2 are pointers to int.

Compare this with: 

int *p1, p2;

Here only p1 is a pointer. p2 is an ordinary int.

⭐ This is one reason typedef can make pointer declarations easier to read.

typedef with Array

typedef int Marks[5];

Marks studentMarks;

studentMarks[0] = 90;

Here Marks represents an array of five ints.

typedef with Function Pointer

Function pointers can be difficult to read. typedef can make them simpler. 

typedef int (*Operation)(int, int);

Now: 

Operation op;

can represent a pointer to a function taking two ints and returning an int.

Complete Function Pointer Example

#include <stdio.h>

typedef int (*Operation)(int, int);

int add(int a, int b)
{
    return a + b;
}

int main()
{
    Operation op = add;

    printf("%d", op(10, 20));

    return 0;
}

🔍 Deeper understanding: Aliases, enumerators and flag design

A typedef creates another name for an existing type; it does not create a distinct type with new checking rules. An enum introduces named integer constants. Enumerator names occupy the ordinary identifier namespace, so two enums in the same scope cannot reuse the same enumerator name without conflict. Do not assume an enum object has exactly the same representation as int in every implementation.

enum Permission {
    PERM_READ  = 1u << 0,
    PERM_WRITE = 1u << 1,
    PERM_EXEC  = 1u << 2
};

Sequential enum values such as 0, 1 and 2 are suitable for mutually exclusive states. Independent flags require powers of two so they can be combined without overlapping bits. A typedef such as typedef unsigned int PermissionSet; improves readability, but values of other unsigned-integer meanings can still be assigned; the alias does not create a protected abstract type.

Common Mistakes

  • Assuming enum always occupies exactly 4 bytes.
  • Thinking typedef creates a completely new type.
  • Confusing typedef with #define.
  • Forgetting the semicolon after an enum or typedef declaration.
  • Confusing an enum type with its individual enumerator names.
  • Using confusing typedef names that hide pointer or array behavior.
Reasoning trace:
1u<<0 = 001 → 1u<<1 = 010 → 1u<<2 = 100 → OR combines without overlap
📘 Standard and portability note

A typedef is an alias, not a distinct strongly checked type. Enum representation can be implementation-dependent.

🧠 Deep Dive — enum Values, Flags, typedef Aliases and Type Design

Enumerators Are Named Integer Constants

enum Day
{
    MONDAY,
    TUESDAY,
    WEDNESDAY
};

If no explicit value is supplied, the first enumerator has value 0 and each following enumerator is one greater than the previous one. You can override values:

enum HttpStatus
{
    HTTP_OK = 200,
    HTTP_NOT_FOUND = 404,
    HTTP_SERVER_ERROR = 500
};

Enumeration values do not have to be consecutive, and different enumerator names may even have the same integer value when the design intentionally uses aliases.

State Values and Bit Flags Are Different Designs

For one-of-many states, sequential values are usually natural:

enum State { IDLE, RUNNING, STOPPED };

Only one state is intended at a time. For independently combinable options, powers of two are more appropriate:

enum Permission
{
    CAN_READ  = 1u << 0,
    CAN_WRITE = 1u << 1,
    CAN_EXEC  = 1u << 2
};

unsigned int permissions = CAN_READ | CAN_WRITE;
Why powers of two?
CAN_READ   = 001
CAN_WRITE  = 010
CAN_EXEC   = 100
READ|WRITE = 011

Each option owns a separate bit, so OR combines flags and AND tests them without ambiguity.

Do Not Use an enum Object as a Promise of a Specific Binary Size

An implementation chooses an integer type capable of representing the enumeration's values according to the rules of the C version and implementation. For portable file formats, hardware registers or protocols, define the external representation explicitly instead of assuming every enum object is exactly four bytes.

typedef Renames a Type — It Does Not Create a Strong New Type

typedef unsigned long UserId;
typedef unsigned long ProductId;

UserId u = 10;
ProductId p = 20;
u = p;  /* allowed: both are aliases of the same underlying type */

The aliases can improve readability, but C does not treat UserId and ProductId as incompatible new types merely because the typedef names differ.

Pointer typedefs Can Hide Important Syntax

typedef int *IntPtr;

const IntPtr p = &x;

Because IntPtr already means int *, the declaration above makes p a const pointer to int, not a pointer to const int. Compare it with:

const int *q = &x;   /* pointer to const int */
⚠️ Why this matters

A typedef can make complex declarations readable, but it can also hide pointer or array structure. Use names that make ownership and mutability clear, especially in APIs.

Using a Sentinel Enumerator for Array Sizes

enum Color
{
    COLOR_RED,
    COLOR_GREEN,
    COLOR_BLUE,
    COLOR_COUNT
};

const char *names[COLOR_COUNT] = {
    "red", "green", "blue"
};

This pattern is useful when values are contiguous from zero and COLOR_COUNT is deliberately kept as the final enumerator. It is not appropriate when enumerators use arbitrary external numbers such as 200 or 404.

INTERVIEW PREPARATION

🎤 Enumerations & typedef — Interview Questions







1.
What is an enum in C?





                An enum defines a set of named integer constants that represent related fixed choices.
            







2.
What value does the first enumerator receive by default?





                It receives 0 unless an explicit value is assigned.
            







3.
Can enum values be assigned explicitly?





                Yes. Any enumerator can be assigned an integer constant expression, and later unspecified values continue from the previous value plus one.
            







4.
What does typedef do?





                typedef introduces an alias for an existing type; it does not create a new runtime object.
            







5.
Why is typedef often used with struct?





                It allows code to use a concise type name without repeatedly writing the struct keyword.
            







6.
Why can typedef with pointers be confusing?





                An alias can hide the pointer nature of a declaration, and qualifiers such as const can then apply differently than beginners expect.
            







7.
Can typedef simplify function pointers?





                Yes. It is one of the most useful cases because it turns complex function-pointer declarations into readable type names.
            







8.
What is the difference between typedef and #define?





                typedef is handled by the C type system and creates a type alias; #define is preprocessor substitution and does not understand C types.
            









PLACEMENT TIPS

💡 Enumerations & typedef — Placement Tips


    

  • Use enum when a variable should represent one value from a fixed, meaningful set of choices.
    • 

  • Remember that default enum values begin at 0 and increase by 1 unless you assign explicit values.
    • 

  • typedef creates a type alias; it does not allocate memory or create a variable.
    • 

  • typedef struct {{ ... }} Name; is a common pattern for cleaner structure declarations.
    • 

  • Function-pointer typedefs are especially valuable because they make callback and operation declarations easier to read.
    • 

  • Do not confuse typedef with #define: one works with C types, while the other performs preprocessing substitution.
    •
